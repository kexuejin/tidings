# ── 结论 ─────────────────────────────────────────────────────────────────────
# 群图 10MB 上限在真机端到端成立：同一个 15MiB 文件，带群引用就停下来等用户，
# 不带就自动收下；接收后 md5 与源文件一致，拒绝后不落盘。
#
# 发送侧本来发不出这个场景：TransferManager.offerFiles 恒发 null 的 groupId/groupRev，
# 而 FileCtlOffer 线级模型早就有这两个字段 —— 收端规则正确，发端从不按规则标注。
# 本批把 groupId/groupRev 一路接到 /v1/send-file（成对校验，只给一个就 400）。
#
# 仍未覆盖：
#   * 群图的**发送侧 UI**：本客户端还没有群的模型（grp1 未声明），界面上发不出群图，
#     这条验收走的是控制面。等群聊落地时，界面必须把 groupId 一起带上，否则同一条规则
#     会在界面那条路径上重新失效。
#   * `purpose` 为 sticker / update 时的内联上限（同一条 isMedia 分支，未在真机跑）。
#   * 大文件续传（断点 .part 恢复）仍未真机跑过。
