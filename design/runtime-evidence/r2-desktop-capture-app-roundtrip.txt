1. 怎么做的（手段）
----------------------------------------------------------------------
本机无 cliclick、/usr/bin/python3 无 Quartz 模块，故自建 5 个 Swift 小工具（均在 /tmp）：
  /tmp/winlist.swift          CGWindowListCopyWindowInfo，列指定进程的 id/name/layer/alpha/onscreen/bounds
  /tmp/avg.swift  png x y w h 区域平均 RGB
  /tmp/ratio.swift base cur   48×27 网格比值图（. ≥0.85 未变暗 / o 0.6–0.85 / # ≤0.6 变暗）
  /tmp/click.swift x y        CGEvent 合成真实左键按下+抬起
  /tmp/drag.swift x1 y1 x2 y2 CGEvent 合成真实拖拽（12 步、每步 60ms）
  /tmp/key.swift vk [cmd|shift|alt]  CGEvent 合成按键（vk 13=W、53=Esc）

启动（不装 /Applications，直接跑产物里的可执行文件）：
  "$APP/Contents/MacOS/捎话 Tidings" > /tmp/r2-app.log 2>&1 &
主窗口几何：CGWindowList 报 (X=48, Y=78, W=1100, H=720)；screencapture 全屏 1920×1080，1 dp = 1 px。

4. 失败与已知副作用（如实记录）
----------------------------------------------------------------------
F1 焦点被抢：本机其他应用（Edge/DSH GUI、WorkBuddy 等）会在命令序列中途抢到前台，
   于是「先点菜单、隔 0.6s 再点条目」这类跨秒序列会打到别的窗口上。
   实测多次出现：frontmost 检查通过 → 点击 → 覆盖窗却没有出现（点落到别的 app）。
   结论：这类合成事件取证只在**单次点击、且点击前 0.3s 内确认 frontmost** 时才可信。
F2 坐标错读：第一次把菜单项位置读错（用缩放图换算），点在条目之间的空隙，点了三、四轮才发现。
   改用 screencapture -R 的 **1:1 crop** 再量，坐标才稳定。
F3 **严重副作用（如实上报）**：我用 /tmp/key.swift 13 cmd 想取消覆盖窗时，
   当时最前的 app 是 Edge（DSH Web GUI），那一发 ⌘W 关掉了用户浏览器的一个标签页
   （原标签「…RelayPanel…」）。此后不再在未核实 frontmost 的情况下投任何带修饰键的全局键。
F4 我启动的实例后来退出了：pgrep 无进程、/tmp/r2-app.log 停在 5 行且无异常，
   ~/Library/Logs/DiagnosticReports 里**没有**它的崩溃报告 ⇒ 是正常退出（很可能是 F3 那发 ⌘W
   或窗口关闭请求走到了应用的退出路径），不是崩溃。无法归因到截图流程。
F5 Esc 取消无效（不是环境问题，是代码问题，见第 5 节）。

5. 顺带发现的 d-capture / d-capture-tools 真缺口（★ 建议单独立项）
----------------------------------------------------------------------
现象：点一次截图后，初始态屏幕上**只有一层 45% 黑遮罩**，没有浮动工具条、没有提示文案、
      没有「取消」按钮；按 Esc 也不取消（实测 3 次：System Events 与 CGEvent 53 都不触发），
      只能 ⌘W（关窗请求 → Window(onCloseRequest = capture.onCancel)，DesktopWindow.kt:355-404）或强退。
对比原型：prototype/screenshots/relay/d28-capture.png 与 d29-capture-tools.png 的初始态
      **都有**浮动工具条（scissors/arrow/text/mosaic/…/×/copy/✓ + 640×480 尺寸标签 + 取消）
      与「拖框选区域 · Esc 取消」提示。
根因（源码）：
  · desktopApp/src/main/kotlin/app/relay/desktop/capture/CaptureOverlayView.kt:337
      if (sel != null && sel.width > 20f && sel.height > 20f && !isDraggingSelection) { 工具条 }
    ⇒ 没有选区就没有工具条，也就没有「取消」按钮（工具条体 :347-455；onCancel 按钮 :423-433）；
  · 同文件 :196-211 把 Key.Escape 收在 Box.onPreviewKeyEvent 上，而该 Box 没有可聚焦子节点，
    焦点不在它身上时按键被丢 —— 这就是 Esc 无效的原因。
修点也在 CaptureOverlayView.kt（desktopApp 模块），**不在 W5 的 R2 写域**，需 Lead 裁决/授权。
补充：Layoutlib 到不了 AWT/JWindow，这正是 d-capture / d-capture-tools 走宿主轨（只能人工并排签收）的原因。
工具条定位函数（可作为改后验收的几何依据）：
  desktopApp/.../capture/CaptureGeometry.kt placeCaptureToolbar(selection, toolbar=CaptureSize(400f,44f),
  viewport, margin=8f, gap=8f)：优先选区下方 sel.y+sel.height+8，放不下翻到上方，再不行夹在 margin 内；
  mapCaptureRectToImage(rect, viewport, image) 用 X/Y 独立换算消 Retina 误差。
