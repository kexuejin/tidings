# Android 真机「收到文本 → 弹通知 → 落盘」证据（Pixel 6, SERIAL-TEST-01, Android 15 / SDK 35, 1080x2400, density 420）
# 对端: 证据节点 aeb471f0-84da-43f3-8444-536719656776（Mac 192.0.2.82, UDP 17893 / TCP 17894）
# 取证时间: 2026-10-07 02:08–02:10

对应 ACCEPTANCE.md 的 A2（通知）与 A1 里「冷启动后恢复出上次的会话线程」那一条。
发送侧是 Mac 上的 agentNode 控制面，接收侧是装在 Pixel 6 上的 `app.relay`。

## 1. 发送（Mac → 手机，单播到手机的 UDP 17878）

$ curl -sS -X POST http://127.0.0.1:8799/v1/send -H "Authorization: Bearer $RELAY_EV_TOKEN" \
    -d '{"to":"192.0.2.22","port":17878,"text":"真机接收方向验收：这是一条从 Mac 上的 agentNode 发出的消息，用来验证 Pixel 6 能收到、能落盘、能弹通知。"}'

## 2. 系统通知真的弹了（A2）

$ adb shell dumpsys notification --noredact | grep -A6 'pkg=app.relay'
    NotificationRecord(... pkg=app.relay ... key=0|app.relay|1001|null|12428:
        Notification(channel=relay_messages_v2 ... importance=3 ... vis=PRIVATE))
            when=1791310092886/1791310092886
                android.title=String (证据节点)
                android.text=String (真机接收方向验收：这是一条从 Mac 上的 agentNode 发出的消息，用来验证 Pixel 6 能收到、能落盘、能弹通知。)

读法：`importance=3`、`channel=relay_messages_v2`（Android 8+ 必须带渠道，渠道名见
`P2-22`），标题是**对端昵称**而不是 nodeId。这一条是 ARCHITECTURE.md 里「接收方向没有真机
跑过」的正面证据。

## 4. 落盘（A1 的持久化）

$ adb shell run-as app.relay ls -l files/relay/
total 8
-rw------- 1 u0_a2428 u0_a2428 1223 2026-10-07 02:08 messages.json
-rw------- 1 u0_a2428 u0_a2428  189 2026-10-07 02:06 settings.json

读法：消息库就是这一个 json（1223 字节，时间戳 02:08 与收到消息同分钟）。

## 5. 冷启动后消息还在（标题会先退化成 nodeId 前 8 位，再由 presence 换回来）

$ adb shell am force-stop app.relay
$ adb shell am start -n app.relay/.app.MainActivity
$ python3 /tmp/pxd.py dump | grep -E "aeb471f0|证据节点"      # 启动后 6 秒
text='aeb471f0'   desc=''  click=false [252,1083][444,1132]
$ sleep 40
$ python3 /tmp/pxd.py dump | grep -E "aeb471f0|证据节点"      # 启动后 46 秒
text='证据节点'   desc=''  click=false [252,866][425,927]

读法：消息本体（预览文本、未读、时间）冷启动后仍在，退化的是**标题**，因为节点表是内存表、
重启后为空 —— 对端资料靠 `presence` 换回来，取证与修法见
`scaffold/design/runtime-evidence/profile-refresh-android-restart.txt`。
