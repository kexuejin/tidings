媒体内联预览（README TODO ⑥）—— Android 真机 + iOS 模拟器
================================================================

要回答的问题
------------
README 的 TODO 里写着「图片与语音能作为文件收到，但聊天里只画文件卡，没有内联预览」。
这一轮补上内联预览之后，要回答三件事：

1. 收到一张图，聊天里真的画出缩略图吗（而不是仍然一张普通文件卡）？
2. 收到一段语音，有没有一个能按的「播放」按钮？按下去真的出声吗？
3. 解不出来的时候（格式不认、文件不在、宿主没有解码器）会不会崩、会不会画空框？

- 收端 A：Pixel 6 `SERIAL-TEST-01`（Android 15 / SDK 35），nodeId

  udp 17888 / tcp 17889，`manualPeers` 指证据节点 `127.0.0.1:17893`。
- 两个测试文件：
  - `/tmp/a6-photo.png`，19743 字节，sha256

方法
----
图片用 `purpose:"image"` 发（收端按 `TransferManager` 的既有规则自动接收，不用点「接收」），
语音用 `purpose:"share"` 发（收端停在报价卡上，需要点一次「接收」）——
这两种用途正好覆盖两条收件路径。判读靠 `uiautomator dump` / `idb ui describe-all` 的
可访问性树 + 截图，不看日志猜。

- **图片**：报价后自动接收，聊天里出现缩略图：绿渐变底、白圆、白字 `RELAY 06`，
  与源文件逐字一致。卡片文案 `a6-photo.png / 19 KB / 已接收 /
  已存到 /data/user/0/app.relay/files/relay/downloads/a6-photo.png/a6-photo.png`
  + 「打开」「分享」两个按钮。**Android 的 `BitmapFactory` 真机解码成立。**
- **语音**：点「接收」（`接收` frame `[147,1909][221,1962]`，tap `184 1935`）后
  出现 `播放` frame `[131,1860][190,1900]`。tap `160 1880` → logcat：
  `AudioTrack: stop(211): called with 22050 frames delivered`
  —— 正好 1 秒 × 22050 Hz，**整段播完**（不是只起了个头）。
  界面上没有出现「这台设备放不了这个格式」，进程存活。
  `MediaPlayer: mediaplayer went away with unhandled events` 是「在 completion 回调里
  release」的标准告警，无害。

过程里查出的两件事
------------------
1. **`mediaKindOf` 的第一版判据是错的，真机才暴露。** 第一版写成
   「`purpose` 非空且不在 `FilePurpose.MEDIA` 里 → 不是媒体」，于是对端带
   `purpose:"share"` 发来的 `.m4a` 被判成普通文件、**没有「播放」按钮**。
   根因：`scaffold/agentNode/src/main/kotlin/app/relay/agent/ControlPlane.kt:293` 对
   `purpose` **不做校验、原样转发**，对端塞任何字符串都到得了这里。改法是「只认协议里
   真的存在的用途」：`purpose` 是 `image`/`sticker` 就是图，是 `FilePurpose.ALL` 里
   别的值就按声明办，**协议里根本没有的值当作没说**、继续按扩展名判。
   新增用例 `anInventedPurposeDoesNotSuppressTheExtension` 钉住。
2. **证据节点跑着旧类路径会让所有文件传输报「传输失败：closed」。**
   `/tmp/relay-ev-node.log` 里是 `java.lang.NoClassDefFoundError:
   app/relay/core/protocol/ErrFrame` at
   `app.relay.core.transport.TransferServer.serve(TransferServer.kt:287)`，
   收端看到的只是 `TransferClient.kt:441 val channel = read ?: fail("closed")` 这一句
   —— 症状与病因隔了整整一层。这是本仓记过的「跑门禁会重建 `agentNode.jar`，
   打断常驻证据节点」的又一次现身。修法：`/tmp/relay-gate.sh :agentNode:installDist`
   之后重启证据节点；**重启前必须先确认旧进程真的死了**（`pkill -f '…证据节点'` 在本机
   匹配不到 java 启动器的命令行，得按 `lsof -nP -iUDP:17893` 查到的 PID 直接 kill，
   否则新进程 `BindException` 退出、HTTP 还是旧进程在答，看起来「重启了但没用」）。

仍未覆盖
--------
- **发端自己的缩略图没在真机上验。** `FileCardUi.localPaths`（发端本地路径）那条路
  要等对端点「接收」、卡片走到 `TransferState.Completed` 才画，而本机唯一能当收端的
  agentNode **从不接受入站报价**（`grep accept agentNode/src/main` 只有 WebSocket 的
  `s.accept()`），所以「我发出去的图在我这边也显示缩略图」只有单测与截图覆盖。
- **缩略图只在内存里。** 文件卡片本来就不落盘
  （`scaffold/composeApp/src/commonMain/kotlin/app/relay/app/RelayUiState.kt:617
  internal fun MessageUi.toStorable(): MessageUi = copy(file = null, …)`），
  重启之后卡片连同缩略图一起消失 —— 既有设计，不是这轮引入的。
- **桌面只验到编译与截图。** `ImageDecoding.jvm.kt` 走 skiko 的 `Image.makeFromEncoded`，
  真窗口里没手工点过；桌面音频只认 WAV/AIFF/AU（JDK 内置解码器的边界），m4a/mp3
  会如实返回 false 并显示「这台设备放不了这个格式」，这条也没在真桌面验过。
- **播放没有进度、没有停止。** 三个平台的播放器都只报「开始失败」不报「已播完」，
  所以按钮语义是「从头播一遍」、不画任何播放中状态 —— 做一个不会自己复位的
  「正在播放/停止」切换按钮正是本仓点名过的「界面状态过期没自愈」。
