# ── 结论 ─────────────────────────────────────────────────────────────────────
# tbl1 的文字视图在真机端到端成立：开关出现与翻转、真制表符/换行、列对齐、
# 无 tableText 时开关不出现、超限时如实标注截断。
#
# 发端本来写不出这个场景：offerFiles 没有 tableText 参数，收端却一直在读。
# 本批把 tableText 接到 /v1/send-file，截断归传输层（路由原样转发，不替它截）。
# 顺带修掉一个自己引入的线级缺陷：truncateTableText 第一版在未截断时返回 false，
# 于是 "tableTextTruncated":false 会出现在**每一个**报价上（含普通文件），
# 老端整帧丢弃 —— 现在没截断就是 null，键不出现。

# 仍未覆盖：
#   * 横向滚动本身（长行是否真能拖动）没有单独验，只验了"不折行"。
#   * C5 的**群 @ 我**那半条：见下面「群 @ 我」一节 —— 不是"还没跑"，是本机
#     造不出发送端、而且界面上根本没有 @ 标记这个呈现。
#   * `tableText` 只在 image 报价上有协议意义；其它 purpose 带它属于未定义组合，没有验。

# ── C5 的「群 @ 我」那半条：为什么跑不了，以及它实际是什么 ────────────────────
#
# 结论：这一条不能靠"发一条群消息看有没有 @ 高亮"来验收，因为
#   (1) 本机没有群消息发送端，(2) 聊天界面里根本没有 @ 高亮这个呈现。
#
# (1) 没有发送端（2026-10-07 复查）
#   $ grep -rn 'groupTextPayload' scaffold --include=*.kt
#   scaffold/core/src/commonMain/kotlin/app/relay/core/protocol/Codec.kt:392:    fun groupTextPayload(
#   scaffold/core/src/commonTest/kotlin/app/relay/core/protocol/GoldenVectorTest.kt:137
#   → 全仓只有「定义 + 一条测试调用」，**零生产调用方**：手机端发不出群消息。
#   agentNode 控制面也没有群路由，只有
#   POST /v1/send、/v1/send-file、/v1/nudge、/v1/agent/session、/v1/agent/event、GET /v1/inbox。
#   所以"直接发一条带 mentions 的群消息"这条路在本机不存在。
#
# (2) 没有 @ 呈现
#   $ grep -rn 'mentions\|MENTION_ALL\|mentioned' \
#       scaffold/composeApp/src/commonMain/kotlin/app/relay/feature/ \
#       scaffold/composeApp/src/commonMain/kotlin/app/relay/ui/ --include=*.kt
#   → 0 命中。气泡里没有"@ 我"的视觉标记。这不是"还没验"，是当前产品没有这个呈现。
#
# 那么 mentions 在真机上到底影响什么？只有通知策略这一件事：
#   scaffold/composeApp/src/commonMain/kotlin/app/relay/app/RelayController.kt:1154
#     mentioned = mentionsSelf(envelope, _state.value.selfNodeId)
#   RelayController.kt:1698  internal fun mentionsSelf(envelope: Envelope, selfNodeId: String): Boolean
#   RelayController.kt:1704  id == selfNodeId || id == MENTION_ALL
#   RelayController.kt:1712  internal const val MENTION_ALL: String = "@all"
#   → 非静默时段，群消息默认不提醒，只有 @ 我（或 @all）才提醒。
#   这半条的另一半（在会话列表上标出"有人 @ 我"）**没有实现**，
#   代码里写明了：RelayController.kt:1725。
#
# 所以 C5 的「群 @ 我」能落到真机上的可观测行为只剩"通知策略里的群 mentionOnly 分支"，
# 而通知策略本身已在 scaffold/design/runtime-evidence/notify-android-policy.txt
# 里用三个开关（Agent 分类 / 静默时段 / 权限被拒）在真机判读过。
# 群 mentionOnly 这一支在本机造不出发送端，因此不能单独复现 —— 如实记在这里，
# 不假装跑过。@ 高亮与会话列表标记两项：代码层确认不存在/未实现，属产品现状，
# 不是验收缺口。
