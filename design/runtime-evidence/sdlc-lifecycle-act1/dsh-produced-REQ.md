# 紫外线出行建议 · 需求说明

> 文档类型：SDLC Harness Requirement（REQ）  
> 特性标识：UV-ADVICE  
> 版本：v1.0  
> 状态：待实现（本文只定义需求，不包含实现与测试改动）  
> 关联文档：`docs/PRD.md`、`docs/DESIGN.md`

## 1. 背景与目标

成功态已展示温度、湿度、风速、空气质量与 7 天预报，但用户看不到紫外线信息，也不知道当前 UV 指数是否适合长时间户外活动。

本特性在成功态增加「紫外线出行建议」模块：把 provider 提供的 UV 指数归一化为非负整数，按固定边界分为四级，并给出与等级一一对应的出行建议。目标如下：

1. **分级确定**：相同输入在任何环境得到相同等级，边界无歧义。
2. **建议可执行**：每个等级都有固定、可断言的防晒/出行文案。
3. **降级安全**：数据缺失或非法时显示「暂无数据」，不崩溃、不误报为「弱」、不影响其他模块。
4. **可自动化验收**：归一化、分级、文案与渲染均有稳定契约，可在 `node --test` 中断言。

## 2. 范围

### 2.1 本期包含

- 成功态的紫外线指数展示、等级标签与出行建议；
- 原始 UV 标量的归一化与四档分级；
- 缺失、非法输入的安全降级；
- 供自动化测试使用的稳定模型字段与 DOM 测试钩子；
- 纯逻辑单测与成功态渲染测试。

### 2.2 本期不包含

- 逐小时、逐日 UV 预报或历史曲线；
- 基于定位、肤色、年龄、用药情况的个性化建议；
- 推送通知、账号体系、多语言；
- 真实气象 API 接入；
- 修改城市搜索、缓存、单位切换、错误态、空气质量、7 天预报的既有行为。

## 3. 数据契约

### 3.1 输入

provider 的成功结果新增**可选**顶层字段 `uvIndex`，与 `tempC`、`humidity` 同级：

```js
{
  city: '北京市',
  tempC: 22,
  humidity: 45,
  uvIndex: 7, // 可选：number | string | null | undefined
  // ...其他既有字段保持不变
}
```

约束：

- `uvIndex` 只接受标量；对象、数组（包括 `{ value: 7 }`）一律按非法输入处理，不做隐式解包。
- 字段缺失与显式 `null` 等价，均表示「暂无数据」。
- provider 有真实数据时，应把数据源的 UV 字段映射到 `uvIndex`；映射层不得把缺失值填成 `0`。
- 默认 fixture 当前没有 UV 字段。实现阶段应补充覆盖四个等级的样例值以便浏览器验收；AC1–AC3 使用构造输入，不依赖 fixture 的具体数值。

### 3.2 输出模型

纯逻辑统一返回以下稳定模型，所有字段必须始终存在，不得返回 `undefined` 字段：

```js
// 有效数据
{
  available: true,
  value: 7,          // 归一化后的非负整数
  valueText: '7',    // 展示文本；有效时等于 String(value)
  levelKey: 'high',  // low | moderate | high | veryHigh
  label: '强',       // 弱 | 中等 | 强 | 极强
  advice: '紫外线强，10:00-16:00 尽量减少户外停留，外出做好防晒。'
}

// 缺失或非法数据
{
  available: false,
  value: null,
  valueText: '--',
  levelKey: 'unavailable',
  label: '暂无数据',
  advice: '暂无紫外线数据，请根据实际天气做好防晒。'
}
```

### 3.3 可测试接口

纯逻辑必须独立于 DOM，放在可被 `node --test` 直接导入的模块中（建议 `src/utils/uv.js`），并至少导出：

```js
export function buildUvAdviceModel(rawUvIndex) { /* ... */ }
```

`buildUvAdviceModel` 是 AC1–AC3 的唯一契约入口；内部是否拆分 `normalizeUvIndex`、`classifyUvIndex` 等函数不限。视图层必须消费该模型，不得在 DOM 代码中重复实现分级规则。

## 4. UV 指数分级与建议

### 4.1 分级边界（规范）

**UV 指数分级（归一化后）：0-2 弱 / 3-5 中等 / 6-7 强 / 8+ 极强。**

| levelKey | 等级 | 归一化后取值范围 | 判定表达式 |
|---|---|---|---|
| `low` | 弱 | 0-2 | `0 <= v && v <= 2` |
| `moderate` | 中等 | 3-5 | `3 <= v && v <= 5` |
| `high` | 强 | 6-7 | `6 <= v && v <= 7` |
| `veryHigh` | 极强 | 8+ | `v >= 8` |

四个等级互斥且完备，覆盖所有归一化后的非负整数，不得出现未分类值。`8` 必须为「极强」，`7` 必须为「强」，`5` 必须为「中等」，`2` 必须为「弱」。`8+` 不设上限，`11`、`15`、`999` 均归为「极强」。

本特性按产品口径把 8 及以上统一为「极强」，不再拆分 11+ 的第五级；这是与部分气象标准不同的地方。

### 4.2 归一化规则

1. 数值类型：必须是有限数（`Number.isFinite`），且 `>= 0`；负数在取整前直接判非法，不能因四舍五入变成 `0`。
2. 数值取整：使用 `Math.round`（正数半值向上），例如 `2.49 -> 2`、`2.5 -> 3`、`7.5 -> 8`。
3. 字符串类型：先 `trim()`；仅接受 ASCII 十进制数字字符串，格式为 `^(?:\d+(?:\.\d+)?|\.\d+)$`；再转为数值并按第 2 条取整。`'+7'`、`'1e2'`、`'0x10'`、`'7abc'` 均非法。
4. 分级和展示必须使用**同一个**归一化整数，避免出现「显示 3、判为弱」这类不一致。
5. `0` 与 `'0'` 是合法输入，表示「弱」；不能与缺失值混淆。
6. 归一化后的 `value` 为非负整数，`valueText` 为它的十进制字符串。

示例：

| 原始输入 | 归一化 value | 等级 |
|---|---|---|
| `0` | `0` | 弱 |
| `2.49` | `2` | 弱 |
| `2.5` | `3` | 中等 |
| `5.5` | `6` | 强 |
| `7.49` | `7` | 强 |
| `7.5` | `8` | 极强 |
| `' 10.2 '` | `10` | 极强 |
| `15` | `15` | 极强 |

### 4.3 建议文案（规范）

每个等级必须映射到固定文案，文案逐字一致，不得为空或复用其他等级的文案：

| levelKey | 等级 | advice |
|---|---|---|
| `low` | 弱 | `紫外线较弱，可正常安排户外活动。` |
| `moderate` | 中等 | `紫外线中等，外出请涂抹防晒霜并佩戴遮阳帽。` |
| `high` | 强 | `紫外线强，10:00-16:00 尽量减少户外停留，外出做好防晒。` |
| `veryHigh` | 极强 | `紫外线极强，避免长时间户外活动，外出须全面防晒。` |
| `unavailable` | 暂无数据 | `暂无紫外线数据，请根据实际天气做好防晒。` |

## 5. 非法输入与缺失数据处理

以下输入统一返回 3.2 节定义的 `unavailable` 模型：

| 输入类别 | 示例 |
|---|---|
| 缺失值 | `null`、`undefined` |
| 空字符串 | `''`、`'   '` |
| 非数字字符串 | `'abc'`、`'7abc'`、`'7.5.1'`、`'NaN'`、`'Infinity'` |
| 非十进制字符串 | `'0x10'`、`'1e2'`、`'+7'` |
| 非有限数 | `NaN`、`Infinity`、`-Infinity` |
| 负数 | `-1`、`-0.1` |
| 非数值类型 | `true`、`false`、`[]`、`{}`、`{ value: 7 }`、函数 |
| 超范围但合法的高值 | `8`、`11`、`999`（有效，极强；不截断为 8） |

处理要求：

1. **不抛异常**：任何非法输入都不得抛 `TypeError`、`RangeError` 等异常。
2. **不误报**：不得把缺失或非法值当成 `0`，不得显示为「弱」。
3. **不进入错误态**：UV 数据有问题时，天气查询仍为 `SUCCESS`，不显示整页错误，不触发重试。
4. **不影响其他模块**：当前天气、7 天预报、空气质量必须继续正常渲染。
5. **不泄漏坏文本**：页面和模型展示文本中不得出现 `NaN`、`Infinity`、`undefined` 等占位内容；不可用状态固定使用 `--` 与「暂无数据」。
6. **不污染数据**：不得修改原始 `data`、缓存对象或其他字段；UV 模型只作为视图派生数据。

## 6. 展示与交互要求

- 成功态必须存在一个独立的「紫外线出行建议」卡片，与当前天气、空气质量、7 天预报并列展示；具体前后顺序不作为验收条件。
- 卡片可见标题为 `紫外线出行建议`。
- 有效数据展示：UV 数值、等级标签、建议文案。
- 缺失或非法数据仍展示卡片，但数值为 `--`、等级为 `暂无数据`、文案使用兜底文案；不得隐藏整个模块或让页面空白。
- UV 与温度单位无关；摄氏/华氏切换后，UV 数值、等级、文案保持不变。
- 颜色不能是唯一等级信号，必须同时有文字标签。
- 稳定 DOM 测试钩子：
  - 卡片：`data-testid="uv-card"`，并以 `data-level` 输出 `low|moderate|high|veryHigh|unavailable`；
  - 数值：`data-testid="uv-value"`，有效时为 `7` 这类纯数字文本，不可用时为 `--`；
  - 等级：`data-testid="uv-category"`，文本为 `弱|中等|强|极强|暂无数据`；
  - 建议：`data-testid="uv-advice"`，文本为 4.3 节对应文案；
  - 卡片 `aria-label`：有效时为 `紫外线指数 7，强`（按实际值替换），不可用时为 `紫外线指数暂无数据`。

## 7. 验收标准（AC）

> 本节 4 条 AC 全部针对「紫外线出行建议」，与 `docs/PRD.md` 的 AC1–AC8 独立编号。  
> 每条 AC 都必须能由 `node --test` 自动执行；不接受「目测」「大致」「合理」等主观判据。

### AC1：分级边界与归一化结果精确

**判据**：给定 `buildUvAdviceModel(raw)`，对下列输入返回的 `value`、`valueText`、`levelKey`、`label` 必须与表一致；`2/3`、`5/6`、`7/8` 三组边界不得串档。

| 输入 | value | valueText | levelKey | label |
|---|---|---|---|---|
| `0` | `0` | `'0'` | `low` | 弱 |
| `2` | `2` | `'2'` | `low` | 弱 |
| `2.49` | `2` | `'2'` | `low` | 弱 |
| `2.5` | `3` | `'3'` | `moderate` | 中等 |
| `3` | `3` | `'3'` | `moderate` | 中等 |
| `5` | `5` | `'5'` | `moderate` | 中等 |
| `5.5` | `6` | `'6'` | `high` | 强 |
| `6` | `6` | `'6'` | `high` | 强 |
| `7` | `7` | `'7'` | `high` | 强 |
| `7.49` | `7` | `'7'` | `high` | 强 |
| `7.5` | `8` | `'8'` | `veryHigh` | 极强 |
| `8` | `8` | `'8'` | `veryHigh` | 极强 |
| `11` | `11` | `'11'` | `veryHigh` | 极强 |
| `999` | `999` | `'999'` | `veryHigh` | 极强 |
| `'7'` | `7` | `'7'` | `high` | 强 |
| `' 10.2 '` | `10` | `'10'` | `veryHigh` | 极强 |
| `'0'` | `0` | `'0'` | `low` | 弱 |

**自动化验证**：在 `test/uv.test.js` 中使用表驱动用例逐行断言上述四个字段。必须覆盖 `0/2/3/5/6/7/8` 全部整数边界，以及 `2.49/2.5`、`7.49/7.5` 两组取整边界。  
**失败判定示例**：`8` 被判为「强」、`2.5` 被判为「弱」、`'7'` 被判为不可用、`999` 被截断为 `8` 或「强」，均判失败。

### AC2：非法输入与缺失数据安全降级

**判据**：对以下每个输入调用 `buildUvAdviceModel`，都必须不抛异常，并返回同一降级模型：

```text
null, undefined, '', '   ', 'abc', '7abc', '7.5.1',
'NaN', 'Infinity', '0x10', '1e2', '+7',
NaN, Infinity, -Infinity, -1, -0.1,
true, false, [], {}, { value: 7 }, function () { return 7; }
```

降级模型必须满足：

```js
{
  available: false,
  value: null,          // 必须是 null，不是 0
  valueText: '--',
  levelKey: 'unavailable',
  label: '暂无数据',
  advice: '暂无紫外线数据，请根据实际天气做好防晒。'
}
```

同时验证：

- `0` 和 `'0'` 仍是合法输入，返回 `low` / 弱，防止 `if (!value)` 之类的假值判断误伤；
- `-0.1` 不得因四舍五入变成 `0` / 弱；
- 模型对象中不得出现 `NaN`、`Infinity` 或 `undefined` 字段值。

**自动化验证**：在 `test/uv.test.js` 中遍历上述非法输入，逐项断言不抛错且降级字段精确相等；另起用例断言 `0` 与 `'0'` 为合法弱。  
**失败判定示例**：任一非法输入抛异常、`value` 为 `0`、等级为 `low`、`advice` 为空或页面出现 `NaN`，均判失败。

### AC3：建议文案与等级一一对应

**判据**：每个等级的代表输入必须返回 4.3 节规定的 `label` 与 `advice`，逐字一致，不得复用其他等级文案：

| 输入 | levelKey | label | advice |
|---|---|---|---|
| `1` | `low` | 弱 | `紫外线较弱，可正常安排户外活动。` |
| `4` | `moderate` | 中等 | `紫外线中等，外出请涂抹防晒霜并佩戴遮阳帽。` |
| `6` | `high` | 强 | `紫外线强，10:00-16:00 尽量减少户外停留，外出做好防晒。` |
| `8` | `veryHigh` | 极强 | `紫外线极强，避免长时间户外活动，外出须全面防晒。` |
| `null` | `unavailable` | 暂无数据 | `暂无紫外线数据，请根据实际天气做好防晒。` |

额外要求：

- 四个有效等级的 `advice` 必须两两不同，且均非空；
- 建议中不得出现 `undefined`、`null`、`NaN` 等占位词；
- 对 `0..20` 的整数遍历时，每个值都必须落入且只落入 4.1 节四个等级之一，不得出现 `unavailable`。

**自动化验证**：在 `test/uv.test.js` 中做表驱动逐字断言，并补充 `0..20` 全量遍历断言。  
**失败判定示例**：任意等级文案为空、两个等级共用文案、`8` 的文案仍为「强」等级文案、有效整数被判为不可用，均判失败。

### AC4：成功态渲染、降级与既有模块不受影响

**判据**：调用 `renderSuccess(container, data, unit)` 后：

1. 当 `data.uvIndex === 7` 时：
   - 恰好存在 1 个 `data-testid="uv-card"`；
   - `data-level` 为 `high`；
   - `uv-value` 文本为 `7`，`uv-category` 为 `强`；
   - `uv-advice` 逐字等于 `紫外线强，10:00-16:00 尽量减少户外停留，外出做好防晒。`；
   - 卡片 `aria-label` 为 `紫外线指数 7，强`；
   - 卡片标题包含 `紫外线出行建议`。
2. 当 `data.uvIndex` 分别为 `undefined`、`null`、`'abc'` 时：
   - 不抛异常；
   - `uv-card` 仍存在且 `data-level` 为 `unavailable`；
   - `uv-value` 为 `--`，`uv-category` 为 `暂无数据`，`uv-advice` 为兜底文案；
   - `aria-label` 为 `紫外线指数暂无数据`；
   - 当前天气（`current-weather`）、空气质量（`air-quality`）、7 天预报（`forecast-weather`）仍正常渲染，`forecast-row` 数量仍为 7。
3. 使用同一份数据分别以 `'C'`、`'F'` 调用 `renderSuccess` 时，UV 的数值、等级、文案完全不变（UV 无单位）。
4. UV 卡片文本中不得出现 `NaN`、`Infinity`、`undefined`。
5. `npm test` 全绿，既有测试断言不得为适配本特性而放宽。

**自动化验证**：新增 `test/uvView.test.js`，复用仓库现有 `FakeElement`/`findByTestId` 方式做 DOM 断言；执行 `npm test` 确认全仓回归。  
**失败判定示例**：缺失 UV 时页面抛错或白屏、UV 卡片被隐藏、`uv-value` 显示 `0`、`forecast-row` 少于 7、C/F 切换后 UV 变化、任一既有测试失败，均判失败。
