# 全端真机与外设交互物理验收 SOP (Physical Acceptance SOP)

> **核心原则**：自动化测试（900+ 单元测试、93 张布局截图、回环套接字）止步于“进程内与本机回环”。
> 真实外设交互、操作系统沙盒边界与硬件传感设备必须按照本标准作业程序（SOP）逐项物理走查并存档留痕。

---

## 模块 1：双机实体摄像头对屏扫码链路 (Camera Pairing SOP)

针对 Android CameraX 与 iOS AVCaptureSession 进行真实镜头与像素识别校验。

### 1.1 实验设备与拓扑
- **展示端（设备 A）**：MacBook Pro 屏幕 或 iPad / 手机 A。
- **扫码端（设备 B）**：Pixel 6 (Android 15) 或 iPhone 真实物理机。
- **环境条件**：正常室内光照（300–500 lux），无强烈逆光，屏幕亮度适中（50%–80%）。

### 1.2 标准操作规程 (SOP)
1. **生成二维码**：
   - 设备 A 打开捎话，进入「节点」页 → 点击本机卡片下方的「我的二维码」；
   - 验证：屏幕展示清晰的白底黑码，下方展示真实节点 URI（如 `relay://192.168.1.100:17878`）。
2. **启动扫码**：
   - 设备 B 打开捎话，进入「节点」页 → 点击右上角「添加节点」→「扫码配对」→ 点击「打开相机扫码」。
3. **权限核验**：
   - 若首次打开，检查系统权限弹窗文本规范（Android 提示“允许捎话拍照”，iOS 提示 NSCameraUsageDescription 文案）；
   - 允许权限后，系统状态栏必须出现绿色相机隐私圆点。
4. **对屏对焦与识别**：
   - 将设备 B 的摄像头对准设备 A 屏幕上的二维码，保持距离在 15cm–30cm；
   - 观察取景框画面：画面流畅、无撕裂、无镜像反转；
   - **时间判定**：在完全框入后 **1.5 秒内** 必须触发成功震动/回调并自动关闭扫码页、退回节点页；
   - **状态判定**：设备 B 的节点列表内新增设备 A，且状态栏弹出“已向 [IP:Port] 打招呼，等它回应”。
5. **异常分支物理走查**：
   - **遮挡/模糊测试**：用手指遮挡二维码中央或晃动手机，验证界面保持稳定取景，不闪退；
   - **非捎话码测试**：将摄像头对准微信/支付宝收款码或普通网页网址，验证系统必须弹出“这不是捎话的配对码”提示横幅，不可误识别或闪退；
   - **物理返回测试**：在相机取景状态下，按物理返回键或点击左上角关闭按钮，验证立刻释放相机并平滑返回上一页，后台无泄露。

## 模块 2：真实操作系统文件打开与分享交互实测 (OS File Exit SOP)

验证文件在跨端接收落盘后，通过操作系统原生接口（Android FileProvider / iOS UIDocumentInteractionController / macOS Finder）成功打开与导出的交互。

### 2.1 测试矩阵与交互规范

| 操作系统 | 接口调用实现 | 预期“打开”交互 | 预期“分享”交互 | 异常兜底机制 |
| :--- | :--- | :--- | :--- | :--- |
| **Android 15** (Pixel 6) | `FileProvider` (`content://`) + `ACTION_VIEW` / `ACTION_SEND` | 系统默认相册/文档查看器打开，无 `FileUriExposedException` | 呼出系统 BottomSheet 原生分享面板，展示附近分享及可用应用 | 若无支持应用，优雅提示“未找到可打开此文件的应用” |
| **iOS** (iPhone) | `UIDocumentInteractionController` + `UIActivityViewController` | 呼出系统 Quick Look 全屏预览界面，图片/音视频即时渲染 | 呼出 iOS 系统 Activity 分享菜单（隔空投送、存储到文件等） | 异常捕获记录 NSLog，不抛出异常导致崩溃 |
| **macOS** (Finder) | `Desktop.open` + `Desktop.browseFileDirectory` | 调用默认应用（如“预览.app”查看图片，“文本编辑”查看日志） | **Finder 激活并高亮选中该文件**（而不是仅打开目录） | 若无默认程序，降级调用 Finder 定位，后台记录 ASCII 诊断 |
| **Windows 11** | `Desktop.open` + `explorer.exe /select,` | 关联程序打开文件 | 资源管理器激活并高亮定位文件 | 降级打开所在目录 |

### 2.2 标准走查步骤
1. **构造测试文件**：
   - 文本类：`report_sample.tsv`（用于配合 `tbl1` 表格测试）；
   - 图像类：高分辨率 PNG 图像（`sample_hero.png`）；
   - 文档类：`archive.zip` 或 `.pdf`。
2. **点对点传输**：
   - 发送方发起传输；接收方点击文件卡片上的“接收”按钮；
   - 确认卡片进度从 `0%` 平滑到达 `100%`，卡片状态切换为“已完成”，并标注实际保存路径。
3. **打开操作走查**：
   - 点击文件卡片下方的“打开”按钮；
   - 验证原生默认程序秒级启动并载入目标文件；关闭外部程序后捎话应用界面正常保持运行。
4. **分享/定位操作走查**：
   - 点击文件卡片下方的“分享”按钮；
   - 桌面端：验证访达（Finder）/ 资源管理器弹出，并精准聚焦选中该特定文件；
   - 移动端：验证原生分享菜单展示，点击“存储到文件”或发送给三方应用能成功导出副本。
5. **落盘完整性比对**：
   - 在终端使用 `shasum -a 256 <原文件> <接收端落盘文件>` 进行校验，两者 SHA-256 必须严格一致。

## 模块 3：桌面端 `ImeSmokePane` 中文输入法 6 大边界手工走查协议

桌面端自检位于：**设置窗口 →「输入法自检」分段**（由 `ImeSmokePane.kt` 提供实时观测台）。

### 3.1 观测台指标说明
- **当前文本** (`TextFieldValue.text`)
- **组合区间** (`TextFieldValue.composition`)：形如 `5..10（正在预编辑）`
- **光标/选区** (`TextFieldValue.selection`)：形如 `12..12`
- **上屏回调次数**：每触发一次 `onValueChange` 递增 1
- **失焦前后值对比**：记录焦点切出瞬间的数据落定行为

### 3.2 六大边界判定标准与签字要求

#### 边界 1：候选窗跟随光标 (Candidate Window Tracking)
- **操作**：在单行与多行输入框中，键入一段拼音后，使用左右方向键移动光标，并用鼠标在文字之间随机点击更改光标位置。
- **看什么**：系统 IME 候选词悬浮窗是否**紧密贴合光标闪烁位置**。
- **合格判定**：光标移动到行首、行尾、文字正中间、换行后首位，候选框均跟随移动，不出现停留在窗口左上角或屏幕边缘偏移的现象。

#### 边界 2：内联预编辑区间 (Inline Pre-edit Composition)
- **操作**：键入拼音字母（如 `nihao`），**不要按空格或回车选词**。
- **看什么**：
  1. 输入框内部是否内联展示带下划线的拼音字母（而不是仅在候选条中显示）；
  2. 观测台「组合区间」是否清晰显示为非空范围（如 `0..5（正在预编辑）`）。
- **合格判定**：输入框与观测台均正确反映预编辑状态。

#### 边界 3：选词上屏与回调吞吐 (Commit & onValueChange)
- **操作**：在边界 2 状态下，敲击数字键 1 或空格键，选择词语“你好”完成上屏。
- **看什么**：
  1. 「上屏回调次数」计数器是否立刻 +1；
  2. 「组合区间」是否干净重置为 `无（未在预编辑）`；
  3. 「当前文本」是否完全变为上屏词。
- **合格判定**：计数器稳定增加，无死锁，无空回调。

#### 边界 4：中英文状态动态切换 (IME Mode Switching)
- **操作**：
  1. 使用 Caps Lock 或 Shift 切换为英文模式，快速键入 `quickstart` 并回车；
  2. 切换回中文输入法，键入 `ce_shi` 并选词“测试”。
- **看什么**：英文输入阶段组合区间全程为 `无`；切回中文后预编辑区间恢复正常；两次输入均能完整上屏。
- **合格判定**：模式切换不丢失击键，无输入法卡死或吞字。

#### 边界 5：退格键删除拼音字符 (Backspace Deletion)
- **操作**：键入 `shurufa`（输入法拼音，共 7 个字母）不选词，连续轻敲 7 次退格键（Backspace）。
- **看什么**：每次退格，观测台「组合区间」是否逐个字符同步缩短（`0..7` → `0..6` → … → `0..0`）。
- **合格判定**：逐字母删除，最后一次退格后组合区间彻底清零，不出现一次退格整串清空或光标错位。

#### 边界 6：焦点丢失数据处理 (Focus Loss Behavior)
- **操作**：在预编辑包含拼音（如 `relay`）的状态下，鼠标直接点击页面上的「移走焦点」按钮或窗口外部。
- **看什么**：查看观测台“失焦前 → 失焦后”判读行。
- **三种行为定义与结论归档**：
  - `A 提交`：拼音文本直接作为文字落入框内；
  - `B 丢弃`：预编辑拼音被清空，但正常触发清空回调；
  - `C 静默丢弃`：预编辑丢弃且未触发 `onValueChange`。
- **合格判定**：产品层必须在聊天输入框内与测试结论保持一致，杜绝“用户以为输入了却在切窗口时无声丢失”的未定义异常。
