# Team Folder 最终方案

> **状态**：待评审，尚未全量落地（分支 `feat/team-folder-phase0`）
> **本文性质**：决策文档。**只看这一份就能开工**；过程对账、被撤销的断言、基线解锁清单都在
> [`team-agent-interaction-and-orchestration-spec.md`](team-agent-interaction-and-orchestration-spec.md)，
> 两者冲突时**以本文为准**。
> **一句话**：团队不新增页面，它就是**一条会话行 + 可展开的成员列表**；折叠只收起成员，
> 不收起会话信息。不做一级 tab，不做"默认/团队"样式切换。

---

## 0. 结论

| 问题 | 结论 |
|---|---|
| 混合进列表，还是独立 tab？ | **混合**。团队是"某个群的一个属性"，不是一级目的地 |
| 要不要"默认样式 / 团队样式"切换？ | **不做**。两套视图 × 两端 × 桌面四档 = 8 个组合要验，且默认态把团队藏起来 |
| 要不要独立团队页？ | **不做一级页**。四个直接对标（飞书 / Slack / LobeHub / dsh-bot-team）没有一家做；有独立页的都是"状态中心" |
| 一个群能有多个团队吗？ | **能**。`GroupMeta.virtualAgents` 是 `List`；聚合键 `(convId, leaderAgentId)`，同群多团队各出一组，同 leader 跨群**不合并** |
| 折叠后信息会丢吗？ | **不许丢**。这就是当前实现要改的原因（见 §3） |

## 1. 目标形态（唯一形态）

列表里挂了团队的群，**仍然是一条普通会话行**，只是行内多一枚团队标记：

```
┌─────────────────────────────────────────────┐
│ ●  智能研发团队           2 条      3 人  − │  ← 会话行本体：群名/未读/时间全在
│    你：收到，组头我按文件夹那版做   3 分钟前  │     + 团队标记（运行点·成员数·折叠符号）
├─────────────────────────────────────────────┤
│      c   coder      编码                     │  ← 展开后缩进画成员行
│      r   reviewer   审查                     │     （折叠时这些行不存在）
│      t   tester     验收                     │
└─────────────────────────────────────────────┘
```

| 交互 | 行为 |
|---|---|
| 点整行 | 进该群会话（与普通会话行完全一致：滑动、长按菜单、置顶、免打扰都继承） |
| 点行尾 `+`/`−` | 只折叠/展开成员；独立热区，不冒泡到整行 |
| 点成员行 | 进群会话并预填 `@<leader> `（壳没有草稿入口时整行不可点，而不是点了没反应） |

**三条不可动摇的约束**：折叠不改变排序（位置永远跟随该会话）、不新增会话实体（会话键仍是
`group:<groupId>`）、不改变未读口径（未读跟着会话行走）。

## 2. 为什么不是另外三种

| 方案 | 否决理由 | 竞品依据 |
|---|---|---|
| **一级 tab**（第 6 格） | ① 两端一级导航各 5 格已满（手机 `AppNavItems` / 桌面 `DesktopView`）；② 团队没有会话身份，协议里只有 `agentId`/`hostNodeId`/`name`/`entityType`/`teamMembers`，没有 `pluginId`、没有独立 `convId`、没有自己的未读与最后消息 —— 做 tab 就得新造实体，把"`team-*` 被判私聊 → 静默无帧"那个口子重开；③ 一级项带徽标，团队消息本来已计入"消息"的未读，会算两遍 | 飞书：多个 bot 进**同一个群**、`@` 接力、指定 lead 统筹；Slack：agent 加进**频道**或 DM；LobeHub：**群组即团队**。无一家做团队一级页 |
| **默认/团队切换** | 8 个组合要截图签收，之后每次改列表验两遍；默认态下团队完全不可见，用户不知道这个群里有团队 | 无对标做这个切换 |
| **独立团队页** | 需要团队会话身份（同上）；且我们的模型比竞品多一层（竞品是 1 群 = 1 团队或 1 群 = 多 bot 无 team 实体），没有现成答案可抄 | Claude Code 的 `agent view` 是按**状态**分组（working / needs input / done）；Slack "Agents & tools" 是**每个 agent 一个中心**。都是状态中心，不是团队页 |

**可借鉴的两个零件**（都不在本轮范围）：① **可折叠手工文件夹 + 拖排序**（`dsh-bot-team`
把它做成了侧栏插件）—— 解决"列表不好整理"，但那是用户手工组织，不是从元数据推导；
② **状态中心**（谁在跑 / 谁等审批）—— 真要做得单独立项。

## 3. 与当前分支实现的差异（这是本轮要改的全部）

当前分支已经跑通"能折叠"，但形态是**组头替代会话行**，代价是丢信息：

| 现状 | 问题 | 目标 |
|---|---|---|
| `TeamFolderHeader` 替代会话行 | 只画 状态点/标题/成员数/未读/符号 —— **没有最后一条消息、没有时间** | 会话行原样保留，团队标记内嵌 |
| 组头标题 = leader 的 `@token`（`devops-swarm`） | 折叠后认不出是哪个群 | 标题 = 会话行标题（群名），token 只在展开态出现 |
| 展开后把会话行补回来 | 同一条会话两个表示 | 不再需要：行一直都在 |
| `FeedRow.Folder.unread` 承接未读 | 为"替代"打的补丁 | 删除（未读跟着行走） |
| `FeedRow.Member` 挂在 `Folder` 下 | 依赖"替代"结构 | 改为挂在会话行之后 |

改造量（四个文件 + 测试 + 两帧）：

1. `TeamFolderProjection.kt`：`FeedRow.Folder` 删除；折叠态只出 `Item(conv)`；展开态出
   `Item(conv)` + 若干 `Member`。**投影因此变简单**（不再需要 `sessionRowEmitted`）。
2. `ConversationRow.kt`：新增一个可选尾部槽（团队运行点 + `N 个成员` + 折叠符号），
   默认 null ⇒ 现有调用零变化。**不新写第二套会话行排版**。
3. `ConversationListPanel.kt`：把"哪些会话有团队、是否展开、回调"三件事传给会话行；成员行
   仍作为独立行插在该行之后。
4. `ConversationsScreen.kt` / `DesktopConversationsPane.kt`：**不用动**（仍是屏幕级 `remember`
   + 参数透传，桌面四档已接好）。

## 4. 裁决清单

| # | 裁决 | 理由 |
|---|---|---|
| D1 | 形态 = **会话行 + 可展开成员列表** | 折叠不得丢预览与时间；这是"混合"里唯一不缺信息的形态 |
| D2 | 标题用**群名**，leader 的 `@token` 只在展开态显示 | 折叠态必须能认出是哪个会话 |
| D3 | 聚合键 `(convId, leaderAgentId)` | 一个群可挂多个团队；`pluginId` 在协议里不存在，只能取 leader 的 `agentId` |
| D4 | 状态复用 `agent-session.state`：`BUSY` = 运行中；该 leader 名下**任一**会话 BUSY 即亮；无会话 = 空闲 | 不自造判活层（`Process.isAlive` 单判会给假 Idle）；`any` 避免一条刚结束的旧会话盖掉正在跑的 |
| D5 | **不重排**，位置跟随该会话 | 排序唯一真源仍是 `orderInboxFeed` / `orderConversationList` |
| D6 | 未读跟着会话行走，不单独承接 | 副标按全部会话求和，两处必须同源 |
| D7 | 手工组织（自定义文件夹/排序）**本轮不做** | 那是"把折叠泛化成任意文件夹"，方向性扩展，需单独立项 |

## 5. 落地步骤

### P0 改形态（本轮，唯一必须做的）

- 投影按 §3 重写：折叠 = 一行；展开 = 一行 + N 成员行。
- `ConversationRow` 加可选尾部槽；团队标记与折叠符号画在槽里。
- 成员行不画在"组内"，而是紧跟会话行、缩进一级；**成员行之间不画分隔线**。
- 测试改：折叠时 `rows.size == 1` 且是会话行；展开时首行仍是同一条会话行（不重复）；
  多团队各出一组；key 唯一。
- 两帧参考图重渲（`chat-home-team-folder` / `-expanded`）。

### P1 数据正确性

- 标题走会话行（群名），展开态成员行旁标 leader 的 `@token`。
- 状态点读 `AgentSessionStates.BUSY`，大小写归一、同宿主匹配（`peerId == hostNodeId`）。

### P2 独立立项（不在本轮）

- 状态中心（谁在跑 / 谁等审批）、手工文件夹、原型折叠态（等 `designScreenDiff` 13 组存量红
  清零，清单见 spec §7.2）。

## 6. 验收判据

| 层 | 判据 |
|---|---|
| 单元 | 折叠 = 1 行；展开 = 1 行 + N 成员行；同群多团队各一组；key 唯一；未读不丢 |
| 守卫 | 容器必须调投影且吃投影结果；会话行仍是唯一行实现（不许第二套排版）；两帧存在 |
| 截图 | 两帧（折叠/展开）必须能看出：群名、预览、时间、未读、成员数、运行点、折叠符号 |
| 设计门 | `designScreenDiff` 与改动前**逐条一致**（当前口径：13 组存量红，非本功能引入） |
| 真机 | 折叠态点行进群、点符号展开、点成员预填 `@leader`；展开后切走再回来回到折叠（与筛选 chip 行为一致） |

**明确不看什么**：`designScreenDiff` 的 13 组存量红不是本功能的验收项；`validateDebugScreenshotTest`
在本仓本地恒红（参考图未入库），不能当回归信号。

## 7. 不做 / 延期

- 不做：一级 tab、默认/团队样式切换、团队独立页、按团队平铺的页面。
- 延期：原型折叠态（有明确解锁条件）、手工文件夹、状态中心。
- 沿用（不重复设计）：责任链、异厂商审查门、验收门、五 CLI、单卡槽卡片、审批分级、
  沙箱、帧预算、团队插件清单 —— 详见 spec §2 对账表。

## 8. 回退

删掉会话行的可选尾部槽 + 投影里的 `Member` 行型 ⇒ 立即回到今天的扁平会话列表。
**数据层零改动**：不新增表/列、不改协议、不改会话键，回退不需要迁移。

## 9. 竞品依据与信源

| 产品 | 多 agent 的表达 | 有没有独立页 |
|---|---|---|
| 飞书 | 官方文档《Bot @Bot for Complex Tasks》：多个 bot 进同一个群，`@` 接力，指定 lead coordinator；协作过程全程可见、可打断 | 无团队页，agent 就是 bot |
| Slack | agent 可加进频道或 DM；2026-08 起有"Agents 标签/代理中心"，**每个 agent 一个中心**、所有 session 在侧栏；Slack Code 把编码任务开进频道 | 有，但按 agent/session 组织 |
| LobeHub | 官方文档 `usage/agent/agent-team`：**群组即团队**，内置主持人分配任务/协调发言/总结，四种协作模式（顺序/并行/迭代/辩论）；成员在群聊左侧栏增删 | 无，团队就是会话 |
| `dsh-bot-team` | 每个 bot 一个单聊（工位）+ 群聊（会议室）+ **可折叠自定义文件夹、拖排序** | 无，组织层在列表里 |
| Claude Code | 五种并行模式；`agent view` 一屏按**状态**分组；桌面用父子嵌套 | 有，按状态分组 |

**信源等级**：飞书开放平台、Slack Help、LobeHub 官方 docs、`code.claude.com/docs/en/agents`、
npm `dsh-bot-team` 包页（v1.3.0，2026-11 上旬）为一手；第三方横评（kylon.io 等）只采信可与官方
文档交叉验证的部分。Claude 桌面端"二三十个子任务后难以分类"来自官方仓库 issue 反馈与三方分析，
只作规模风险的旁证，不代表普遍结论。
