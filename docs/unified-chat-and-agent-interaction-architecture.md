# 榫卯 (Tenon) 大道至简：1:1 与群聊大一统交互与工作区架构规范 (Unified Interaction & Minimalist Workspace Architecture)

> **规范标识**：`SPEC-UNIFIED-INTERACTION-SIMPLIFIED`  
> **对齐基线**：`SPEC-ORCHESTRATION-2026-11-03` / `SPEC-ORCHESTRATION-P2-REVISED` / `AGENTS.md`  
> **核心哲学**：**大道至简，交互归一，直面真实用户体验**。
> - **概念彻底折叠**：摒弃过度设计的“企业级权限矩阵”与“打字时弹出的单句瞬态胶囊”，工作区回归为最直观的“容器级项目指针”；
> - **1:1 与群聊完全同构**：1:1 是 $N=2$ 的对端直连，群聊是 $N > 2$ 的多端协同。UI 结构、工单卡片、微状态刷新、权限审批流、Diff 审查与一键合并 100% 同构；
> - **工单即会话 (Task as Session)**：聊天流是单向平铺的自然时间线，任务生命周期由动态 TicketCard 承载，彻底废除顶栏伪「切换会话」死控件；
> - **真实终端行为与体验闭环**：杜绝万行日志刷屏，卡片内微状态原位推进，详尽终端移步抽屉或工作区看板；支持主机休眠离线队列、中途轻量切工程、一键合并代码与安全沙箱回收；
> - **零协议与存储破坏**：0 线协议修改，0 数据库迁移，严格遵守信封白名单，不产生任何“发送成功、对端静默丢弃”的致命缺陷。

## 一、 为什么必须「大道至简」？（真实痛点与历史根因剖析）

在以往的迭代中，系统陷入了“功能越堆越多，真实实操却寸步难行”的怪圈。站在**真实拿着手机的开发者**视角，梳理出的深层根因如下：

```text
[真实用户痛点 1] 认知撕裂：我想让电脑帮我写代码，但 1:1 里完全走不通
  · 用户在 1:1 私聊里对 Mac 说“帮我修个 Bug”，结果毫无反应或报 WorkspaceNotFound；
  · 根因：编排器硬写了 resolveWorkspacePath(groupId)，1:1 没有 groupId，任务直接被静默吞掉或 Handback。

[真实用户痛点 2] 迷惑控件：顶栏的「切换会话」到底是干什么的？
  · 1:1 顶栏塞了一个「切换会话」菜单，点开是一堆没有语义的 UUID 或随机串；
  · 选了其中一个，聊天界面的历史消息一条都没变（底层按 peerId 全量查库，根本不按 session 过滤）；
  · 用户发消息，底层文本帧根本不带 sessionId，对端依然不知道切了什么。典型“自欺欺人”的死控件。

[真实用户痛点 3] 操作反人类：打字打到一半强行弹两级抽屉选工作区
  · 设计了 AgentContextCapsule：用户在输入框输入 @agent 时，弹出一个胶囊卡片；
  · 点开弹出一级 BottomSheet 选 Agent，再弹二级 BottomSheet 选 Workspace；
  · 敲个键盘被强行打断数次，心智负担沉重，极易误触关掉。

[真实用户痛点 4] 屏幕被日志摧毁：终端跑一次编译，聊天记录被刷爆 20 页
  · 外部 CLI 产生几千行编译输出与依赖拉取日志，若平铺进聊天流，彻底破坏自然对话体验；
  · 超大日志还会挑战即时通讯网络帧的硬预算（64 KiB），引发协议拒收。
```

**裁决**：交互必须回归常识——**开发者在聊什么项目，系统就该明确感知；任务启动就出一张动态卡片，原位推进；做完看 Diff 一键合并。**

## 二、 业界同类标杆深度调研（证据链）

结合本仓归档的竞品源码调研（`SPEC-ORCHESTRATION-2026-11-03` §17 对 LobeHub、DS Bot 的对账，以及 Cursor、Claude Code、GitHub Copilot Workspace 等），业界共同的铁律清晰明确：

| 标杆工具 / 框架 | 架构范式 | 工作区（Workspace）如何处理？ | 会话中如何切换工作区？ | 核心启示 |
|---|---|---|---|---|
| **Cursor / Windsurf** | 本地 IDE 范式 | **1 窗口 = 1 工作区**。底座深度绑定当前打开的工程根目录。 | **窗口内严禁切工作区**。若要改别的工程，必须 `Open Folder` 新开窗口。聊天内 `@folder` 仅作局部代码检索。 | 工作区是**环境级底座**，不是聊天状态。不同项目必须物理隔离在不同窗口。 |
| **Claude Code / Aider** | CLI 终端范式 | **当前运行目录（`cwd`）即工作区**。执行权限完全受限于当前进程目录。 | **不支持会话内切换**。切换项目必须退出或新开终端 Tab。 | 执行体必须拥有确定、不可歧义的物理目录。 |
| **DS Bot** (`Fei2411/DS-Bot`)<br>*(本仓 §17.4 对账)* | DSH 社区多智能体群聊 | **Room 即工作区容器**。每个 Room 预置 `goal`、管理员与固定成员名册。 | **按 Room 隔离**。群 A 服务于项目 A，群 B 服务于项目 B，群内所有指令自动继承当前 Room 宿主的工作区。 | **谁参与 = 显式配置；环境绑定在频道上**。不搞动态抢单或临时切目录。 |
| **LobeHub**<br>*(本仓 §17.3 对账)* | Agent Group 协同平台 | 预先落库的一等对象。每个 Group 静态绑定 Knowledge Base 与系统提示词。 | 聊天流是连续的，工作区/知识库作为 Session 的静态属性，不随单条消息动态切换。 | 反面教训：LobeHub 尝试过动态绕过 Router 直通 Worker，因失控改回严格确定性路由。 |
| **Slack / Discord** (GitHub / Linear Bot) | 企业 IM 机器人范式 | **频道绑定仓库**（如 `/github subscribe repo`）。1:1 私聊则常驻上次选定的仓库。 | 频道内直接生效；1:1 中通过轻量上下文标签（如 `Repo: [ mobile ▾ ]`）在对话头部单选切换。 | 最符合 IM 交互的轻量解法。 |

**调研结论**：没有任何一款成熟产品允许在“打字单条消息”的瞬间跳跃切换工作区。**工作区必须是稳定的“容器级上下文（Container-level Context）”**。

## 三、 实体物理映射：彻底消除概念打架

系统严格定义五层物理映射，各模块统一口径：

```text
宿主设备 (Host Peer, nodeId) ── 电脑硬件与工具环境 (如 开发者 MacBook)
  └─ 工作区 (Workspace, wsId) ── 电脑上的本地 Git 仓库 (/source/teahouse-mobile)
       └─ 对话容器 (Conversation, convId) ── 用户日常交互界面
            ├─ 群聊 (Group, group:<id>) ── 专案作战室 (1 群 = 1 仓库)
            └─ 私聊 (Direct, <peerId>) ── 对端助手 (顶栏挂接轻量项目药丸)
                 └─ 工单卡片 (TicketCard, ticketId/sessionId) ── 任务生命周期实体
```

1. **宿主设备 (Host Peer)**：提供算力、CLI 驱动与 Git 环境的物理电脑；
2. **工作区 (Workspace)**：电脑上的一个本地 Git 仓库路径（拥有独立的 Git HEAD 与分支）；
3. **协同群 (Project Group)**：**专案作战室**。1 群 = 1 仓库，所有人在该上下文下协同；
4. **1:1 会话 (Direct Chat)**：**对端专属助手**。直接与桌面电脑对话，顶栏挂接项目指针；
5. **工单任务 (TicketCard / Task)**：**会话的真身**。一次需求 = 一张动态卡片，在独立 Worktree 沙箱中运行。

## 四、 真实用户行为与操作全景（User Operational Journey）

真实开发者的操作旅程分为三大核心界面，每个界面的操作直观、顺畅、零打扰：

```
┌──────────────────┐       ┌──────────────────┐       ┌──────────────────┐
│ 1. 会话入口列表   │ ────► │ 2. 1:1 对端助手   │ ────► │ 3. 专案群聊作战室 │
│ 专案与工作站清晰  │       │ 药丸选项目，直接聊│       │ 全员围绕单项目协同│
└──────────────────┘       └──────────────────┘       └──────────────────┘
         │
         ▼
┌──────────────────┐
│ 4. 智能体资产看板 │ (非聊天界面，仅作全局环境体检、日志抽屉与免审租约管理)
└──────────────────┘
```

### 4.1 场景一：1:1 私聊对端操作全流程（极简 Project Pill）

这是单人开发者最核心的高频场景。

#### 1. 进入与顶栏视觉
* 用户打开与 `💻 开发者 Mac` 的 1:1 私聊；
* **顶栏展示**：
  * 主标题：`开发者 Mac`（附带 🟢 在线 / ⚪ 离线 状态点）；
  * 副标题：**轻量项目药丸（Project Pill）**：`📁 teahouse-mobile ▾`；
* **单项目静默锁定**：若 Mac 仅注册了 1 个项目，药丸不显示下拉箭头，不可点击，界面清爽；
* **多项目点击切换**：若 Mac 有多个项目，点击药丸秒级滑出轻量 BottomSheet：
  ```text
  选择工作区 (当前连接: 开发者 Mac)
  ──────────────────────────────────────────
  ● 📁 teahouse-mobile   (/source/teahouse-mobile)   [当前活跃]
  ○ 📁 api-service       (/source/api-service)
  ○ 📁 frontend-web      (/source/frontend-web)
  ──────────────────────────────────────────
  ```
  用户轻触 `api-service`，抽屉收起，顶栏秒变 `📁 api-service ▾`。

#### 2. 中途切换项目的真实行为（操作细节）
* **不影响历史卡片**：如果用户刚才对 `teahouse-mobile` 派了单，聊天流里的旧 TicketCard 依然明确标注 `[📁 teahouse-mobile]`，不会因顶栏切换而变动；
* **时间线轻量提示**：切换后，聊天时间线内插入一条极轻量的本地分割线：  
  `─── 切换当前工作区至 api-service ───`  
  （纯本地 UI 提示，不产生网络帧，不进数据库，给用户清晰的视觉确定感）；
* **后续消息自然送达**：此后用户发送的所有指令，自动路由往 `api-service` 执行。

#### 3. 发送需求与原位单卡推进
* 用户直接在输入框打字：`“优化登录拦截器的 token 刷新机制，增加指数退避重试”`（无需 `@` 任何 Agent）；
* 消息发送后，输入框立即清空，消息气泡上屏；
* **300ms 内，原位弹出唯一动态工单卡片 (TicketCard)**：
  ```text
  ┌────────────────────────────────────────────────────────┐
  │ 📋 工单 #t112: 优化登录拦截器 token 刷新 (api-service) │
  │ 🟡 状态: 正在分析依赖与现有测试... (耗时 12s)          │
  │ 🤖 角色: Worker(Codex) ──► Reviewer(Claude) 待命       │
  │ 📦 沙箱: worktree/t112-auth-backoff                    │
  │                                                        │
  │ [ 🛑 中断任务 ]                                        │
  └────────────────────────────────────────────────────────┘
  ```
* **拒绝万行日志刷屏**：卡片内部只显示最新单行微状态（如 `正在修改 AuthInterceptor.kt (1/2)` ➔ `正在执行 ./gradlew test...`）；
* **查看完整日志抽屉**：用户若想看详细终端输出，轻触卡片主体，右侧/底部滑出 **“执行日志”** 抽屉，聊天流依然干干净净。

#### 4. 敏感权限就地审批（Human Approval）
* 若 Agent 尝试执行危险 Shell 命令或越权写操作，卡片原地浮出审批横幅：
  ```text
  ┌────────────────────────────────────────────────────────┐
  │ ⚠️ 权限申请: 请求执行终端命令                         │
  │ 💻 命令: ./gradlew build --refresh-dependencies        │
  │                                                        │
  │ [ 拒绝 ]      [ 允许本次 ]      [ 本次会话免审 (30分) ]   │
  └────────────────────────────────────────────────────────┘
  ```
* 移动端单手点击 `[ 允许本次 ]`，审批通过信令通过严格白名单立即送达，任务继续推进。

#### 5. 审查 Diff 与一键合入主干
* 自动化测试跑通、异厂商审查 PASS 后，卡片翻绿：
  ```text
  ┌────────────────────────────────────────────────────────┐
  │ 📋 工单 #t112: 优化登录拦截器 token 刷新 (api-service) │
  │ 🟢 状态: 交付就绪 (Claude 审查签字 PASS)               │
  │ 📊 成果: 2 个文件变更 (+48, -12) | 全部 6 个单测通过   │
  │                                                        │
  │ [ 🔍 查看改动 Diff ]         [ 🚀 一键合并到主干 ]       │
  └────────────────────────────────────────────────────────┘
  ```
* **移动端 Diff 审查**：点击 `[ 🔍 查看改动 Diff ]`，原地唤起全屏代码高亮对比抽屉（增绿删红，支持折叠文件）；
* **一键安全合并**：点击 `[ 🚀 一键合并到主干 ]`：
  - 桌面端原子执行 Git 分支快进合并；
  - 触发 `deleteArtifactsSafely()` 安全清理 Worktree（遵守 `AGENTS.md` §2.8，绝对防止软链接穿透）；
  - 卡片更新为终态：`🟣 已合入主干 (commit 7a3f81c) | 沙箱已释放`。

### 4.2 场景二：群聊专案作战室全流程（Project War Room）

* **心智模型**：群聊是团队或多 Agent 共同攻坚特定项目的作战室。
* **1 群 = 1 仓库**：
  - 群顶栏副标题固定显示：`📁 teahouse-mobile`；
  - 群内打字默认为该项目，**彻底移除输入框打字触发的 `AgentContextCapsule` 动态胶囊**；
  - 若需切换项目，直接切换到另一个专案群。
* **点名协同与多 Agent 探讨**：
  - 用户可 `@Claude @DeepSeek 分析下该模块如何重构`；
  - 触发只读研讨流（只读安全锁，无 Worktree，最多 2 轮对账），文末附带 `[ 🚀 按此方案开工 ]` 芯片；
  - 点击一键开工后，群内同样生成单张 TicketCard，全员可见，按序推进。

### 4.3 场景三：桌面主机离线 / 睡眠容错（Offline Resilience）

真实情况下，桌面 Mac 可能会盒盖休眠或断网：
* **软状态感知**：顶栏项目药丸与状态灯变为 `💻 开发者 Mac (离线/休眠)`；
* **离线存储与转发**：
  - 用户依然可以打字发送任务；
  - 消息气泡打上轻量排队图标 `⏳ 等待工作站上线...`；
  - 数据安全进入 `RelayQueueStore` 离线重放队列；
* **开盖瞬间唤醒与补发**：
  - Mac 开盖连上网络后，P2P 链路自动建连（双向 PIN 校验）；
  - 队列严格以 `Codec.decodeTcp` 格式（支持 32 KiB / 64 KiB 预算）重放派单；
  - 手机端 TicketCard 原位被点亮唤醒，任务自动进入沙箱执行，全程无任何丢单或报错弹窗。

### 4.4 场景四：存量 DSH 插件 (`dsh-tenon`) 的无缝融入

* **定位**：运行于宿主 8788 本地端口的外部自治 Agent 桥接插件；
* **协同方式**：
  - 当外部 DSH 运行产生里程碑结果或需要人工审批时，通过统一编排通道向专案群聊或 1:1 投递标准通知或审批横幅；
  - 用户在手机端点击 `[ 允许 ]`，信令回传 8788 端口；
  - DSH 的完整终端日志与会话状态，陈列在 **Tab 2 智能体看板** 中，不入侵、不刷屏 IM 聊天流。

| **成果 Diff 审查** | 点击卡片 `[ 🔍 查看改动 Diff ]` 唤起代码比对 | 点击卡片 `[ 🔍 查看改动 Diff ]` 唤起代码比对 | 100% 同构（移动端高亮代码比对） |

## 六、 协议与存储零破损铁律（Protocol & Storage Invariants）

本架构对底座协议与存储有极度严苛的保护，确保没有任何“破坏性变更”：

### 1. 1:1 卡片传输的严格信封白名单保护
* **避坑警告**：1:1 的单聊纯文本帧 `kind: "text"` 拥有严格白名单：`TEXT_KEYS = setOf("kind", "text", "resend")`。如果向 `text` 帧强塞 `card` 键，接收侧 `hasOnlyKeys` 校验将判定 `extra-field` **整帧拒收**！
* **铁律实现**：
  - 1:1 会话中的工单卡片通过 `kind: "agent-invoke"` / `agent-invoke-result`（具有 `card` 白名单字段）或在宿主生成后通过本地事件驱动落库；
  - 存储层统一写入 `MessageEntity.card_payload` 字段，UI 侧按统一的 TicketCard 组件渲染；
  - 杜绝向单聊 `kind: "text"` 塞非白名单字段，消除第 1 类与第 7 类“静默丢帧”。

### 2. 帧预算铁律（≤ 5 KiB）
* 所有的 Git Diff、代码全文、单测长日志**严禁进入即时通讯网络帧**；
* 网络中流转的 TicketCard 仅携带工单元数据（id、状态、分支名、文件变更计数、审查签字），序列化后体积 ≤ 5 KiB（远低于 24 KiB 的卡片硬预算红线）。

### 3. 0 数据库破坏
* 彻底作废原计划的 `WorkspaceBindingEntity` 等过度设计表（18.sqm / 19.sqm 历史包袱）；
* 会话所选的项目指针仅以轻量字段持久化或保存在内存控制器中，不引入新的 `.sqm` 数据库迁移文件，保证老版本客户端与新版本构建数据库兼容性 100% 稳定。

## 八、 总结：大巧若拙，直面实操

本方案不堆砌任何花哨的“动态权限矩阵”或“瞬态交互魔法”，而是直面**一个拿着手机的工程师如何轻松指挥远端电脑**的真实场景：
- **想在哪个项目干活？** 群聊进群就干，私聊看顶栏药丸；
- **任务怎么执行？** 一句话发过去，一张动态卡片原位推进，微状态实时可见，终端日志不脏聊天；
- **有风险怎么办？** 手机原地弹窗，一键单手审批；
- **代码做完了？** 手机看 Diff，一键合并到主干，沙箱自动回收。

**大道至简，行稳致远。** 这套架构不仅让代码库减少上千行无用复杂度，更让 1:1 与群聊的协同能力第一次真正变得可感知、可落地、坚不可摧。
