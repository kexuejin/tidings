# 榫卯 (Tenon) · 智能体与跨平台用户体验深度优化规范

> **规范标识**：`SPEC-TENON-AGENT-UX-POLISH-2026-V1`  
> **核心定位**：衔接 `project-directory-and-execution-site-model.md`（底层模型）与 `agent-hub-phase-b-final-plan.md`（卡片流方案），针对多端物理差异、弹窗挤压、桌面两栏重复、运行中黑盒焦虑及电脑休眠感知，建立全流程极致用户体验标准。

## 1. 跨平台（移动端 vs 桌面端）物理差异与适配原则

依据 `AGENTS.md §2.6`，组件**核心内容共用一份，外壳参数化适配**。两端存在不可回避的物理级差异：

| 差异维度 | 移动端 (Compact / Phone) | 桌面端 (Expanded / Desktop) |
|---|---|---|
| **物理端口** | **无本地文件系统目录端口**（受沙箱与 SAF 限制，无法自由选择物理路径） | **具备完整目录端口 (`hostDirectoryPort`)**：可原生选目录、跑沙箱、建 Git 分支 |
| **屏幕布局** | **单列纵向流**（无侧边栏、无第三栏检查器；下钻走全屏导航） | **宽屏多栏**（左侧 64dp 导航轨 + 中间主内容 + 右侧 Inspector 检查器侧栏） |
| **弹窗环境** | 高度受限（最多 500~600dp），宽度 360~400dp，**极易出现垂直拥挤与双重滚动** | 窗口视野宽阔，支持分段 Tabs 切换与大卡片自适应展开 |
| **输入交互** | 虚拟软键盘（手打长路径体验极差，严禁要求输入绝对路径） | 实体键盘与鼠标（支持快捷键、文件拖拽与物理目录浏览） |

## 2. 核心体验痛点根治方案

### 2.1 建群弹窗 (`WorkspaceGroupCreateDialog`)：去拥挤与双端分流

#### 现状病灶
1. 上下硬塞了“已有项目列表”与“全新目录输入表单”两个大流程，在 500dp 高度限制下密不透风；
2. 移动端居然画了手动输入物理绝对路径的文本框，属于反人性的伪需求；
3. 卡片右侧硬塞两颗按钮（【进聊天】+【分享码】），横向挤压导致左侧项目名和路径被严重截断。

#### 优化落地规范

```
┌────────────────────────────────────────────────────────┐
│  创建项目协同群                                    [✕]  │
├────────────────────────────────────────────────────────┤
│  ┌──────────────────────────────────────────────────┐  │
│  │   [  已有项目 (3)  ]    |    [  关联本地新目录  ] │  │ <- 桌面端分段 Tabs；移动端仅留已有项目
│  └──────────────────────────────────────────────────┘  │
│                                                        │
│  【分支 A: 已有项目目录（通透卡片流）】                 │
│  ┌──────────────────────────────────────────────────┐  │
│  │ 📁 teahouse-mobile         [已关联协同群]        │  │ <- 整卡可点进入群聊
│  │    ~/source/teahouse-mobile          [打开群聊]  │  │
│  └──────────────────────────────────────────────────┘  │
│  ┌──────────────────────────────────────────────────┐  │
│  │ 📁 backend-service         [未建群]              │  │
│  │    ~/source/backend-service          [+ 一键建群]│  │ <- 右侧单药丸，释放左侧排版
│  └──────────────────────────────────────────────────┘  │
│                                                        │
│  【分支 B: 全新本地目录（仅桌面端展示）】               │
│  选择本地文件夹路径:                                   │
│  [ ~/projects/new-service                         ]    │
│  协同群名称:                                           │
│  [ new-service 协同群                             ]    │
│  ☑️ 自动同步至我的其他设备                              │
│                                                        │
│ ────────────────────────────────────────────────────── │
│                                [ 取消 ]   [ 立即创建 ] │
└────────────────────────────────────────────────────────┘
```

1. **移动端深度裁剪**：
   - 彻底隐藏“全新目录手动输入”分支（手机端无 `hostDirectoryPort`）；
   - 手机端仅保留“已有项目目录快速建群”列表，或提示“由桌面宿主统一管理路径”；
2. **桌面端分段分流 (Segmented Tabs)**：
   - 顶部提供 `[已有项目目录]` 与 `[关联本地新目录]` 双 Tab 切换，彻底消灭中间分割线与内部二次滚动；
3. **卡片横向降噪**：
   - 右侧去掉厚重的并排双按钮，改为整卡可点；
   - 未建群卡片右侧只保留轻量的小药丸 `[+ 一键建群]`，横向空间彻底还给项目名与路径。

### 2.2 审批流：消除桌面端“两栏同屏重复”与手机端“迷宫横跳”

#### 现状病灶
- **桌面端**：右侧 Inspector 检查器已经画了待审批列表，中间主屏（`AgentConsoleScreen`）顶部又画了一遍，左右两栏同屏出现两份一模一样的审批卡片，中间主内容被挤扁；
- **移动端**：群聊中看不全全局审批，主页看审批又缺失群名上下文。

#### 优化落地规范
1. **桌面端条件渲染去重**：
   - 当桌面端处于宽屏状态（`sizeClass.hasInspector` 为 true 且 `DesktopInspectorPane` 激活）时，**中间主屏的 `AgentConsoleScreen` 自动隐藏顶部审批段**，将宝贵的主屏宽度 100% 留给智能体卡片流；
2. **移动端场景化穿透与原位审批**：
   - 智能体主页卡片置顶透出带群名的待审批通知：`⚠️ [移动端群] 待审批: rmdir /tmp/cache [去批准]`；
   - 点击直接原地呼出处置面板，处置完毕自动更新，无需在群聊与主页间来回切换。

### 2.3 运行中任务：消除“黑盒等待与盲等焦虑”

#### 现状病灶
- 派单后执行时间较长，用户不知道 Agent 是正在思考、正在沙箱编写、还是正在跑测试，中途缺乏反馈，且无法随时打断。

#### 优化落地规范
1. **群内轻量阶段反馈**：
   - 群聊顶部进度条 (`GroupProgressBar`) 动态展示当前执行棒位（如：`💻 Coder 正在沙箱编写代码...`、`🛡️ Reviewer 正在审查补丁...`）；
2. **智能体中心动态感知**：
   - 卡片上实时同步真实最新事件文本（如：`⚡ 正在运行单元测试门禁...`），空闲时自动收起为小绿点（`🟢 空闲待命`）；
3. **显式随时中止 (Cancel)**：
   - 运行中条目右侧始终保留一颗清晰的 `[中止]` 按钮，点击直接发送 `agent-cancel` 帧中断执行，掌控感拉满。

### 2.4 跨设备协同：根治电脑休眠引发的“幽灵假死”

#### 现状病灶
- 办公室的 Mac/PC 宿主机休眠后，手机端无感知，用户在群里继续 `@lead` 派单，消息无声入队或死等回复，用户误以为软件故障。

#### 优化落地规范
1. **输入框前置感知**：
   - 群聊输入框呼出 `@` 菜单时，系统检测该 Agent 所在宿主的连接活跃度；若离线或休眠，候选条目旁直接灰显标红：`[电脑休眠中]`；
2. **发送侧友好拦截阻断**：
   - 若用户强行发送任务，输入框上方即时弹出温暖提示：“该智能体宿主 (Mac Studio) 处于休眠状态，唤醒电脑后将自动恢复执行”，消除死信疑惑。

---

### 2.5 产物验收：打通“聊天流 ➔ 智能体卡片 ➔ 文件柜”闭环

#### 现状病灶
- 任务完成后产出的 HTML 原型或 Markdown 规范散落在消息流中，后续回溯极其困难。

#### 优化落地规范
1. **聊天流直达**：
   - 消息气泡中的产物卡片一键调起外部浏览器或系统预览（如通过 `ic_window` 打开 HTML 原型）；
2. **智能体卡片快捷回溯**：
   - 智能体卡片底部展示最近一次成功的交付物标签（如：`📄 最新补丁: PR #128`），点击直达；
3. **文件柜自动归档**：
   - 所有生成的非代码成果物，底层自动归档到底栏 Tab 2【文件柜】，按群和项目目录清晰分类。
   - **落地裁决（不做"搬文件"）**：这一条按**索引**落地，不按**副本**落地。文件柜 Tab 2
     「智能体产物」按项目目录分组列出每件产物的元数据（文件名 / mime / 大小 / 时刻），
     点一行回到**产出它的那条会话**（本体在那儿，由既有文件动作打开）。不复制文件、
     不改任何人的磁盘。裁决理由见 `docs/plans/GOAL.md` §2.5③ 那一段：副本的价值是
     "源没了也能看"，而本产品本地优先、产物就在本机；它换来的是版本爆炸、记账与文件
     寿命不一致、无上限增长、敏感文件扩散这四个静默失效。**唯一改主意的触发条件**是
     实际发生过「产物取不回」，那时的正确修法是延长会话文件保留期。

### 2.6 新手冷启动：把“冷冰冰的空态”变成“10 秒可玩的引导”

#### 现状病灶
- 新用户首次配对设备后进入第四页，看到的是“无工作区、无会话、无数据”的一片灰色，不知所措。

#### 优化落地规范
- **向导式空态 (Warm Onboarding)**：
  未绑定任何项目群时，展示一张精致的引导卡片：
  ```
  ┌────────────────────────────────────────────────────────┐
  │ 🤖 发现局域网可用设备: Mac Studio (在线)               │
  │    该设备已就绪，随时可以为你分配数字员工团队          │
  │    [🚀 立即为它关联第一个项目，开始协同]              │
  └────────────────────────────────────────────────────────┘
  ```
  点击按钮直接呼出精简版建群弹窗，10 秒内完成第一个项目协同群的建立。

## 4. 实施推进计划

| 阶段 | 任务目标 | 关键改动点 |
|---|---|---|
| **第一步 (UI 降噪)** | 建群弹窗彻底重构 (`WorkspaceGroupCreateDialog`) | 桌面端双 Tabs 分流；移动端裁剪手动输入；卡片横向降噪 |
| **第二步 (双端解耦)** | 桌面端两栏去重 (`DesktopShell.kt`) | 宽屏下主屏隐藏冗余审批段，解决内容重复与空间挤压 |

| **第四步 (文案收口)** | 全仓文案统一 (Strings / Gates) | 去“工作区”化；双语对账；门禁与截图夹具更新 |
