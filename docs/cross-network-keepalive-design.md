# 手机主动长连接（跨网下行）设计（task-20 ③）

> **这是设计阶段的提案，不是落地现状。**
> §3 的协议草案、§7 的分期、§8 的未决问题都已被后续实现取代或裁决；
> 落地后的形态看 [`ARCHITECTURE.md`](../ARCHITECTURE.md) §5.4（K1/K2 与传输安全两档）、
> §5.5（跨网直连与候选池）与 [`README.md`](../README.md) 的「长连接下行通道」。
> 两条设计阶段没预料到、真机上才暴露的坑记在这里，供后来者别重踩：
>
> 1. **空闲 5 秒被读超时误判成对端关闭**：握手用的 `socket.soTimeout` 建连后没有复位，
>    于是每条连接每 8.1 秒断一次。修法是握手后 `soTimeout = 0`（`LinkTls.jvmShared.kt`）。
>    证据：[`design/runtime-evidence/link-idle-drop-20261019.md`](../design/runtime-evidence/link-idle-drop-20261019.md)。
> 2. **手机在 Wi-Fi 上够不到 IPv6 的对端**：Android 的路由主表只装默认网络，
>    换到蜂窝之后到对端那条路不在表里。修法是 `NetworkBinder` —— 公网地址先用
>    `ConnectivityManager` 找到能走那张网的 `Network`，再 `bindSocket`（`AndroidNetworkBinder`）。

> 状态：**设计稿，未实现**。本文件只描述形态、与现有路径的关系、NAT/保活/重连与风险。
> 相关：task-19（源地址漂移的刷新）、task-20 ①②（候选池兜底 / 重复配对更新地址）、
> task-13（公网传输安全 + pin）、task-15（Android 后台保活）。

## 0. 结论速览

1. **形态**：手机作为 **client 主动**连主机的一条长连接；主机在这条连接上**回下行**。
   手机发起 ⇒ 天生穿过手机侧 NAT，主机因此**天然知道回程地址**（连接的对端地址）——
   这正是「主机学不到手机运营商地址」那条死锁的根治。
2. 它是**第三条承载**，不是替代 UDP/TCP：UDP 仍负责发现/心跳，TCP 仍负责文件与长文本；
   长连接只在"对端主动方向不可达"时兜底下行。
3. **一上线就要带 TLS + pin**（task-13 已裁决：公网内容只允许经 TLS 的 TCP 通道）。
   明文长连接只允许作为**局域网内**的兜底，且默认关闭。
4. 最大的不确定性不是协议，是**后台存活**（Android Doze / iOS 后台 socket 冻结）——
   那条在 task-15，长连接只是它的消费者。

## 1. 它解决的是哪个问题

今天跨网的死锁（task-19/20 真机复现）：
- 手机在移动网**发不出** UDP 广播（过不了网段），只能单播到它**存着的**主机地址；
- 那个地址如果是局域网 IPv6，就完全不可达；
- 主机因此学不到手机的运营商地址，两边互相显示离线，消息全进队列。

task-19 让主机能从"同 rev 但换了源地址"的 presence 里重新问出地址，task-20 ② 让候选池
兜底 —— 但两者都**依赖手机能把一个包送到主机的某个地址**。如果手机侧一个地址都不通
（主机在对称 NAT 后、或地址全过期），就仍然需要"手机先开口"。

长连接把方向反过来：**手机开口，主机在已建立的连接上回话**。这是 DS-Bot-App 的形态。

## 2. 与现有路径的关系

| 能力 | 今天 | 加长连接后 |
|---|---|---|
| 发现 / 在线判定 | UDP 广播 + 单播 presence | **不变**（广播不可能被长连接取代） |
| 1:1 文本 | UDP 首发 + ACK，失败回退 TCP，再失败入队 | 主机发现"有长连接到该 peer"时，**优先写长连接**；其余不变 |
| 群发 | 逐成员单播 | 对"有长连接的成员"改走长连接；没有的仍走 UDP/TCP |
| 文件 / 屏幕 | 独立 TCP 连接（pull/offer/done） | **不变**（首期不做多路复用） |
| 离线队列 | 落盘、上线补发 | **不变**；长连接重连后也触发一次 flush |
| 候选池 | registry 一个当前地址 + 候选兜底 | 长连接建立时，把该 peer 的当前地址**更新为连接的对端地址**（NAT 外侧） |

关键：**信封格式不变**。长连接只是又一条"字节流"，上面跑的仍是
`4 字节大端长度 + UTF-8 JSON`（`TcpFrame`）与现有 `msg`/`msg-ack` 语义。
这样 ACK/重传/去重/队列/分页全都不用动。

## 3. 最小协议设计（建议）

1. **连接**：手机连主机的 `tcpPort`（默认 17879）。为了不与"文件/长文本"的短连接混淆，
   首帧声明角色：`{"type":"link","nodeId":"<手机>","ver":1}`（新帧类型；旧端收到会按
   未知类型丢弃，不影响它们）。
2. **身份**：主机收到 `link` 后，用现有 `entry` 流程校验/记录该 nodeId，并把
   `registry` 里该 peer 的当前地址更新为**连接的对端地址**（这是收益最大的一步）。
3. **下行**：主机要发给该 peer 的 `msg` 直接写这条连接（帧格式与 TCP 回退一致）；
   手机照常回 `msg-ack`。主机侧仍保留 UDP 路径：长连接写失败/超时即退回原路径。
4. **上行**：手机也可以在这条连接上发 `msg`（省一次候选尝试），主机回 `msg-ack`。
5. **心跳**：连接上每 15s 一个 `{"type":"link-ping"}` / `link-pong`（或复用 `presence`），
   45s 无任何字节判死并重连。
6. **多设备**：一台主机可同时挂多条（每设备一条）；同一 nodeId 重复连接时**保留最新、
   关闭旧的**，避免"两条路同时下行"造成重复。重复消息由现有 `dedupStore` 兜底。

## 4. NAT / 保活 / 重连

- **NAT 映射超时**：运营商 TCP 映射常见 30–120s 空闲即回收。心跳 15s 留足余量；
  不用内核 keepalive（默认 2 小时，等于没有）。
- **半开连接**：TCP 写成功不等于对方活着（NAT 回收后可能只在下一次写时才报错）。
  必须有"无 pong 即判死"的应用层超时，不能只靠 write 返回值。
- **网络切换**：Wi-Fi↔蜂窝会换源地址、旧连接立刻失效。监听平台网络变化
  （Android `ConnectivityManager` / iOS `NWPathMonitor`）**立即**重连，不等退避。
  重连后重发 `link` 身份帧，并触发一次队列 flush。
- **退避**：1s、2s、4s…上限 60s，加 ±20% 抖动，避免所有设备在同一秒重连（惊群）。
- **断线期间**：消息照旧走队列（现有机制），重连只负责"尽快把队列排空"。

## 5. 与 TLS / pin 的关系（硬约束）

task-13 的裁决是"公网对端的内容只允许经 TLS 的 TCP 通道"。这条长连接**承载内容**，
所以：
- 公网上线时必须 **TLS + 双向 pin**（每个节点自签 IP 证书，SPKI 固定）；
- 明文长连接只允许在**局域网**作为兜底，且要有开关（默认关）；
- 否则它就成了绕过 task-13 的那条明文后门。

TLS 的可行性已由 `docs/spike-kmp-tls.md` 证明（三端零新依赖、iOS 无需 Swift）。

## 6. 风险

| 风险 | 说明 | 缓解 |
|---|---|---|
| **后台存活** | Android Doze/App Standby、iOS 后台 socket 冻结会掐掉长连接；这是最大风险 | task-15 的前台服务；把长连接的生命周期挂到它上面；"保活通知"如实说明 |
| **耗电** | 常驻连接 + 15s 心跳 | 心跳合并（有数据时免心跳）、仅在"最近失败过"时保持、Doze 窗口内降频 |
| **运营商 NAT** | 对称 NAT / 映射回收 | 心跳 + 快速重连 + 仍保留 UDP/TCP 原路径 |
| **主机资源** | 每设备一条连接 | 连接数上限 + 每连接鉴权（必须校验 nodeId/授信，否则任意人可占用下行） |
| **双发/重复** | 同一条消息同时走长连接与 UDP | 去重表（已有）+ 明确"谁 ACK 算送达" |
| **安全** | 连接是手机发起的，但主机不能凭"谁连上来"就信任 | 必须用 TLS pin + 授信列表；明文模式只限局域网 |
| **协议复杂度** | 多路复用（一条连接跑多个会话/文件）会引入流控/背压 | 首期**不做**多路复用；一条连接只跑控制与文本 |

## 7. 分期建议

| 期 | 交付 | 验收 |
|---|---|---|
| **K0** | 本设计 + 与 task-13/15 的边界 | 评审通过 |
| **K1** | 手机→主机长连接 + 主机下行文本（**局域网、明文、默认关**）；连接建立时更新 peer 当前地址；断线重连 | 手机在局域网退后台 → 主机下行仍能到；断线 30s 内自动恢复 |
| **K2** | TLS + 双向 pin（task-13 的 P2），公网启用 | 手机只留移动网时，主机下行能到（task-20 的验收） |
| **K3** | 网络切换/Doze 适配 + 电量与连接数治理 | 真机 24h 观察：切换无需人工干预、耗电可接受 |

**回滚**：长连接是"又一条承载"，关掉开关即回到今天的 UDP+TCP+队列；协议上只多一个
`link` 帧类型，旧端会按未知类型丢弃。
