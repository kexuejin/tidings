# experimentalLuciola 转正：默认开（含证据、取舍、共存与回退）

日期：2026-10-27。goal 第 (5) 步的收口。

## 改了什么

| 项 | 之前 | 现在 |
|---|---|---|
| `RelaySettings.experimentalLuciola` 默认值 | `false` | **`true`** |
| 设置页标题 | 已去掉"实验：" | 不变（"luciola 加密信道"） |
| 设置页副标题 | 描述开启后的代价 | 说明**默认开启**、与未升级设备会失去自动发现、**关掉并重启即回退** |

字段名保留 `experimentalLuciola`：改名等于让所有已落盘的用户选择丢失。

## 为什么可以转正（全部是可复核的数）

| 项 | 证据 |
|---|---|
| 文件传输 | 真机 50MB **2.89s / 17 MiB/s**（修复前 90s），sha256 两端一致；回环 566ms / 88-105 MiB/s |
| 投屏帧率 | 正式 5 分钟验收 **4.908 vs 4.909 fps = 99.98%**，39 个窗口**零降档** |
| 端口退役 | 真机两端都**不再监听** 17879 / 17881 / 17882 |
| 数据面 | 消息 / 文件 / 投屏全部走加密信道 |
| 引擎 | APK 内 `.so` 与 AAR 中那份 sha256 一致（`201eab4d…`），两端都是含全部修复的 0.4.6 |

## 默认开之后的实测（本轮，**没有**任何显式开关）

把手机 `settings.json` 里的 `experimentalLuciola` 键**删掉**，让默认值生效：

```
设置里剩下的键: ['nick', 'nodeId', 'persistMessagesDecided']

手机 TCP 监听: :17878  :17880  :17888          ← 无 17879/17881/17882 ✓
宿主看到对端:   {'nick': 'Pixel 6', 'online': True}
1MB 端到端:     [chunk] chunksSent=16 waitMs=105
                [luciola] channel push file=abcd7018 sent=1048576/1048576
                sha256 两端一致 8a60d7c2…
```

**结论：默认开在真机上确实生效，且数据面走的是加密信道。**

## 已知取舍（写进设置页与本文档，不藏）

1. **投屏延迟 1.51×**：55.16ms vs legacy 36.57ms（同条件 5 分钟 A/B）。
   差额来自每次跨 JVM↔Rust 边界的固定开销；**传输段（字节搬运）反而比 legacy 更快**
   （0-4ms vs 3-8ms）。最差窗口 luciola 258ms / legacy 304ms，luciola 更稳。
2. **未升级的老设备会失去自动发现**：开着时 legacy 发现不启动，老版本既发现不到我们、
   我们也发现不到它 —— 它们只会显示成离线，界面上没有任何解释。

## 共存与回退

**回退（用户自助，已验证可走）**：设置里关掉开关 → 重启节点 → 回到 legacy 发现与传输。

**共存（未完全做，如实标注）**：
- 本机对端的**动态提示**（"这台设备可能需要升级"）**还没做**。
  判据已经在控制面准备好了（`/v1/peers` 的 `reachability: legacy-peer-invisible | unknown | ok`，
  且 `caps` 缺失时返回 `unknown` 而不是误判成老端），但移动端设备列表的模型里**没有 `caps` 字段**，
  要显示这条提示需要补一条数据链路。这是已知的下一步，不是遗漏。
- 目前用户能看到的说明只有设置页那一句。

**这次没有验证到的一条**：新版 App ↔ **旧版 App** 之间还能不能靠二维码配对。
手上没有旧版本构建，无法验证。**这是默认开后唯一未被证实的保障**，已记为待办。
