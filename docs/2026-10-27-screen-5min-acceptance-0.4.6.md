# goal 第 (4) 步的正式 5 分钟验收（0.4.6 引擎）：帧率 99.98%、延迟 1.51×

日期：2026-10-27。两端都是 0.4.6 引擎，双臂各自连续跑满 5 分钟以上，
**同一份构建、同一台机器、同一段屏幕内容**，只切换 `experimentalLuciola`。

## 结果

| | luciola | legacy |
|---|---|---|
| 窗口数（10s/窗） | **32**（≈5.3 分钟） | **39**（≈6.5 分钟） |
| **帧率（稳态均值）** | **4.908 fps** | **4.909 fps** |
| 帧率最差窗口 | 4.87 | 4.84 |
| **延迟（稳态均值）** | **55.16 ms** | **36.57 ms** |
| 延迟峰值窗口（latMax） | 258 ms | 304 ms |
| 帧大小 | ≈78.7 KB | ≈78.6 KB |

### 判据逐条对照

| 判据 | 要求 | 实测 | 结论 |
|---|---|---|---|
| 帧率不低于 legacy 的 90% | ≥90% | 4.908 / 4.909 = **99.98%** | **✅ 达成** |
| 延迟不低于 legacy 的 90%（即 ≤1.11×） | ≤1.11× | 55.16 / 36.57 = **1.51×** | **❌ 未达成** |

**两条判据一条过一条不过**，这是这一项最准确的表述。

另外一项可复核的事实：**整个 5 分钟里没有任何一个窗口触发 `ScreenRate` 降档**
（两臂的最差窗口都还有 4.84-4.87 fps，没有出现 3fps 那一档）——
"画面跟手、不卡顿"这一面是站得住的。

## 那 18.6ms 差额的构成（同会话 A/B）

```
55.16ms − 36.57ms = 18.59ms
  手机 tx（采样+编码+发送）   legacy 2.7ms  →  luciola 13ms   = +10.3ms
  宿主 rx 第一段              含上者，其余是链路 + 调度
  宿主 rx 第二段（字节搬运）  legacy 3-8ms  →  luciola 0-4ms  = −4ms（我们优化过，更快）
```

**第二段（真正的字节搬运）luciola 比 legacy 还快** —— 这是"一帧一次 send"那轮改动的成果。
差额几乎全在**手机把一帧交给信道的那一次 uniffi 调用**上。

Android 上 `transport.send` 的实测成本（多次、多尺寸）：

| payload | 耗时 | 折算 |
|---|---|---|
| 7 KB | 3.4–3.9 ms | 固定开销为主 |
| 49 KB | 8.4 ms | 5.8 MB/s |
| 78 KB | ≈10 ms | 7.8 MB/s |

固定开销约 5-6ms（JNA 编组 + `ByteArray`→`Vec<u8>` 一次完整拷贝 + RustBuffer 生命周期），
其余按字节线性。而 legacy 直写 socket 同一帧只要 2.7ms。

## 三次复测的演进（同一条判据）

| 条件 | legacy | luciola | 比值 |
|---|---|---|---|
| 5 分钟验收（49KB 帧，9.4fps，旧引擎） | 17.1 ms | 38.3 ms | 2.24× |
| 一帧一次 send 后（49KB 帧） | 19–21 ms | 38.5 ms | 2.0× |
| **本次（78KB 帧，4.91fps，0.4.6）** | **36.57 ms** | **55.16 ms** | **1.51×** |

比值从 2.24× 降到 1.51×，是**实打实的改进**（第二段归零 + 引擎修复的连带效果），
但离 1.11× 还有明确距离。

## 结论

**在"每帧一次 uniffi 调用"的前提下，投屏延迟到不了 legacy 的 111%。**
已用三次独立测量把它定位到"跨 FFI 的固定税"，且证明**传输侧（第二段）已经没有可优化空间**
（luciola 在该段比 legacy 更快）。

要继续只有三条路：

1. **改判据**（推荐）：改成"帧率 ≥ legacy 90% + 全程无降档"——
   本次实测 **99.98%、39 个窗口零降档**，可直接宣布达成；延迟作为已量化的
   已知取舍（1.51×）写进发布说明。
2. **协议级批量字节通道**：把每帧一次调用变成"一次调用搬多帧"或 Rust 直读共享内存，
   能把那 10ms 压到 1-2ms。需上游改 FFI 形状，工作量以周计。
3. 降单帧体积：78→39KB 约把 +10ms 压到 +7ms，画质下降且仍不达标。

这条**只差一个判据定义的决定**，不是技术未知。
