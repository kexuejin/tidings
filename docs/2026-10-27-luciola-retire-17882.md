# 退役 17882：画面信道覆盖对端候选地址（含前提与证据）

日期：2026-10-27。goal 第 (5) 步的最后一块 —— 17879/17881 已在真机验证退役，
这次把 **17882（跨网投屏 TLS）** 也一并退役。

## 为什么**先**补地址覆盖，**再**退役

17882 是**跨网**投屏的唯一入口（`tlsPort + 2`）。如果直接退役，而画面信道的 opener
只拨 `record.ip`（局域网那一个地址），那么蜂窝/跨网场景就**彻底没有投屏**了 ——
这是"迁移"变成"功能缺失"的典型形态。

所以顺序是：

1. **先**让画面信道按对端候选地址逐条尝试（`screenWireAttempts` 里用
   `registry.candidatesOf(peerId)`，局域网地址天然排在前面 —— 与跨网文件/投屏
   `CrossNetworkTransferPolicy` 同一条纪律）；
2. **再**在信道模式下不创建 17882（`if (!fileChannelEnabled && screenPort != null ...)`）。

## 证据

新增用例 `ScreenChannelWiringTest.secureScreenCoversPublicCandidateAddresses`：

- 对端档案带 `scr1` + `screenPort`，registry 里给一条**公网候选地址**
  （通过 `peerEndpointStore` 注入，与真机"上一次配对/发现学到的地址"同一条路）；
- 断言：`screenWireAttempts` 至少排了 3 条，且**实际试过** `192.168.2.22`（局域网）
  与 `203.0.113.9`（公网候选）两个地址。

这条用例是"退役 17882 不会让跨网投屏消失"的可复核依据 —— 没有它，退役就是一次
静默的功能回退。

## 17879 / 17881 / 17882 三者的退役判据（现在齐全）

| 端口 | 退役实现 | 证据 |
|---|---|---|
| 17879 明文文件 | `TransferManager.legacyTcpListener = !fileChannelEnabled` | 真机 `lsof`：宿主监听里没有 17879 / 17881（`docs/2026-10-26-luciola-realdevice-50mb-acceptance.md`） |
| 17881 跨网文件 TLS | 同上（同一个开关关掉明文与跨网两条入口） | 同上 |
| **17882 跨网投屏 TLS** | `NodeRuntime` 的 `if (!fileChannelEnabled && ...)` | **JVM 层**：`ScreenChannelWiringTest` 两条用例（新路径被优先、覆盖公网候选） |

**诚实标注**：17882 的退役目前只有 JVM 证据，**还没有真机 `lsof` 复核**。
真机复核需要跑一次投屏（跨网场景最佳），当前机器负载过高（load 5.45）且
50MB 验收也跑不过，这一项留给下一轮在干净环境下补。
